## 2. 判据是怎么定下来的（三次推翻）

### 第一次错：以为「出脚 = 字形低于基线」

量了 yMin：Noto -55 / OPPO -37 / HOS -58，OPPO 在「甲/申/明」上反而**更深**（-108/-111/-127）。
→ yMin 不是判据。

### 第二次错：以为「出脚 = 竖条轮廓顶端突出」

用「细长竖条（高>宽×2.5）」找，Noto 19 个字里 12 个 vbar，OPPO 只有 2 个。
看着像判据，但逐个查坐标发现那些 vbar 顶端**与相邻块同高**（明：c5 顶 778.99 = c0 顶 778.99）。
→ 竖条本身不是脚。

### 第三次错：像素剖面测错了对象

用「每列最低墨点」算左右竖腿 vs 中间底横，得出 Noto 16.5u / OPPO 0.0u。
**这个数字是错的**——「中列最底」取到的是内框底边（口 c1 的 y=30），不是底横。
→ 侧列与中列的差其实来自内框位置，不是出脚。

### 正确判据（逐点实测得出）

```
口 c0 (8 点，⊓ 形外壳):
  (127,735) (877,735)      ← 顶横
  (877,-51) (796,-51)      ← 右脚底面
  (796,660) (205,660)      ← 内框顶
  (205,-55) (127,-55)      ← 左脚底面
口 c1 (4 点，独立底横):
  (162,107) (851,107) (851,30) (162,30)   ← 底横 y 30..107
```

**竖腿伸到 y=-55，底横下沿只到 y=30 → 相差 85，这就是出脚。**

OPPO 的结构是「完整外框 c0 底边 y=-37 + 内孔 c1」，底横就在最底部，所以**平底无脚**。

## 3. 做法：把底横下移，而不是把竖腿抬高

```python
# 找：宽扁条（w > h*1.8），被某个高得多的外壳（高 > h*2.5）包含，
#     位于外壳下半部（y1 < shell_y0 + 0.62*shell_h），
#     且 bar_y0 - shell_y0 在 [18, 140] 之间 → 这个差就是出脚量。
drop = bar_y0 - shell_y0
new_bar = [(x, y - drop) for (x, y) in bar]   # 整体下移，纯平移
```

**为什么不抬高竖腿**：抬高会让字形整体 yMin 变化，视觉上整个字「浮起来」，
且竖腿长度缩短会导致与相邻笔画的关系错乱。下移底横保持 yMin 不变，
只把底边做平——这正是 OPPO 的做法。

## 4. 踩到的坑：谚文/假名/拉丁被误伤

第一版不限范围，处理了 **18,387 字**，样例全是 `uni1107`（谚文字母）、`g` 等。

像素差分量化误伤：

| 组 | 改动像素占比 | 最大位移 |
|---|---|---|
| 拉丁 | 20.3% | 97px |
| 谚文 | 12.3% | 58px |
| 假名 | 24.6% | 76px |
| 汉字 | 33.0% | **10px** |

**缩略图上看不出来，必须量化。**

根因：U+1107 的结构是「8 点外壳 + 4 点内条」，和「口」**几何同构**，
判据无法从几何上区分。

**修法**：加 CJK 统一表意文字白名单（URO + Ext-A/B + 兼容 + 康熙部首），
处理量从 18,387 降到 **10,039**（全是汉字）。

复验：`g` / `a` / `가` / `あ` 全部**未变**，只有 `口` / `日` 变。

## 5. 与 glow-sans 的对照

| glow-sans 做法 | 本项目做法 |
|---|---|
| `detect-feet.js` 固定 2° 直角容差 | 用**面积/包含关系**等几何不变量，无固定角度阈值 |
| 「下部 1/4 脚高」补偿 → 字形漂移（issue #7）| 整体平移底横，yMin 不变，无漂移 |
| 光栅化→骨架→重描，曲线被压平 | 直接在 glyf 点集上平移，曲线原样保留 |
| 无 CJK 范围限制 | 显式 CJK 白名单 |
