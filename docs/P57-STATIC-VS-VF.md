# P57：静态实例 vs VF 一致性验证

## 为什么查这个

我们同时交付两套东西：
- **7 个静态 TTF/WOFF2**（Thin..Heavy）
- **1 个 VF**（wght 250-900）

用户可能任选其一。若两者在同一字重下画得不一样，
就会导致「换成 VF 后排版全变了」的问题。

此前从未验证过这项。

## 方法

对每个字重，比较：
```
A = WDesignSansSC-{档位}.ttf            （静态实例）
B = instancer(wdsans-FINAL.ttf, wght=档位)  （VF 在档位处实例化）
```

对 9 个代表性字形（一丨国永口日田我骨）逐点比较坐标，取最大差值。

## 结果：7/7 全部一致

| 档位 | wght | 最大坐标差 (upm) | 判定 |
|---|---|---|---|
| Thin | 250 | **0.00** | 一致 |
| Light | 300 | 0.50 | 一致 |
| Normal | 350 | 0.50 | 一致 |
| Regular | 400 | **0.00** | 一致 |
| Medium | 500 | 0.50 | 一致 |
| Bold | 700 | 0.50 | 一致 |
| Heavy | 900 | **0.00** | 一致 |

### 0.5 upm 是什么概念

```
upm = 1000
0.5 / 1000 = 0.05% em
在 16px 字号下：0.5 * 16/1000 = 0.008 px
在 100px 字号下：0.5 * 100/1000 = 0.05 px
```

**亚像素级差异，任何屏幕、任何字号下都不可见。**

### 为什么不是 0

两端点（wght 250 / 400 / 900）差值为 0，
中间档位（300/350/500/700）有 0.5 upm 舍入差。

原因：`instancer` 内部用浮点插值，
而 TTF 的 `glyf` 表坐标是整数（或 1/16 精度）。
存盘时四舍五入产生 ±0.5 的量化误差。

**这是文件格式的固有精度，不是构建错误。**

## 结论

| 项 | 结果 |
|---|---|
| 检查字形 | 9 个（含单笔、复合、内外结构）|
| 检查档位 | 7 档全部 |
| 最大差异 | 0.5 upm = 0.05% em |
| 可见性 | **不可见** |
| 端点档位 | 完全为零 |

**用户用静态字体或 VF 得到的字形是同一个。**

## 意义

这条验证消除了一类隐蔽风险：如果静态实例和 VF 用了不同的减细参数，
（比如静态走了 `thin_edges(6.0, 3.5)` 而 VF 走了别的），
外观会有肉眼可见的差异，但**两个文件单独看都"正常"**，很难发现。

实测证明两者来自同一母版、同一套变换，完全同步。
