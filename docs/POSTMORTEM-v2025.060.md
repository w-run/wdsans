# 旧版 WDesign Sans（2025.060）失败复盘

> 对 `/var/minis/shared/wdsans202506` 的实测审计。目的是**用数据锁定失败原因**，避免新方案重蹈覆辙。
> 审计日期：2026-10-22

---

## 一、结论速览

旧版不是"改得不够好"，是**结构性失败**。六个独立缺陷，其中三个是不可逆的：

| # | 缺陷 | 是否可修 |
|---|---|---|
| 1 | 点结构不兼容 → 无法出 VF | ❌ 不可逆（需重建） |
| 2 | 特性表被裁剪 → 丢失 locl / 语言变体 | ⚠️ 理论上可补，实际不可行 |
| 3 | 产物经 FontCreator 手工修补 → 不可复现 | ❌ 不可逆 |
| 4 | 中宫方向做反（字变大而非留白变多） | ✅ 可调参数 |
| 5 | 出角处理过度（全局 45° 斜切） | ✅ 可调参数 |
| 6 | 拉丁度量失配（cap 784 vs 中文 733） | ✅ 可调参数 |

---

## 二、实测数据

### 2.1 无法生成可变字体（致命）

插值要求每个字形的**节点数量、顺序、类型完全一致**。实测：

| 对比 | 点结构一致字数 | 占比 |
|---|---|---|
| Regular ↔ Thin | 1958 / 31914 | **6.1%** |
| Regular ↔ Heavy | 1520 / 31914 | **4.8%** |

根因：glow-sans 的管线对每个字重**独立重新生成轮廓**（栅格化 → 骨架提取 → 重描边）。轮廓点数取决于图像处理的分割结果，每个字重都会漂移。

**这不是精度问题，是方法问题。** 任何"重新描边"的路线都必然失败。

### 2.2 特性丢失

```
GSUB features: aalt ccmp dlig fwid hwid liga pwid ruby vert vrt2   （10 个）
GSUB scripts:  DFLT                                                 （1 个）
```

对照 glow-sans 源码 `src/font-build/res/features.js` 的白名单，本来允许 15 个 —— 说明连它自己的白名单都没拿全（缺 `hist`/`jp78`/`jp83`/`jp90`/`nlck`）。

更关键：**`locl` 从来没有过**。倒装句、日式字形差异（直/骨/次/令/海/每）在这个文件里根本不存在。拆分语言是靠"每个语言出独立字体"实现的，而不是 OpenType 的语言标记。

### 2.3 不可复现

```
name ID 5: Version 2025.060;July 8, 2025;FontCreator 15.0.0.2927 64-bit
```

证据链：

| 观察 | 说明 |
|---|---|
| `glyf` 表（TrueType），非 `CFF ` | 经过 CFF→TTF 转换（二次贝塞尔量化） |
| Mona 的 `o` 有 32 点，这里 56 点 | 转换时二次曲线转三次或反之，点数膨胀 |
| Mona 的 `H` 有 3 个轮廓，这里 1 个 | 手工合并重叠轮廓 |
| `fvar` / `gvar` 不存在 | 纯静态，无任何可变结构 |

→ 产物无法从源码重建。每改一次都要在 GUI 里重做一遍，这是"很多显示错误用手动替换"的必然代价。

### 2.4 中宫做反了

| 指标 | 实测 | 说明 |
|---|---|---|
| CJK bbox 高度中位 | **920 / 1000** | 字面撑到 92% |
| CJK bbox 宽度中位 | **895 / 1000** | — |
| bbox 面积占 em² | **0.82** | 留白极少 |

参数 `counter: 1.048` + `ytracking: 1.045` 的作用是**把骨架整体向外推**。字变大了，但笔画间留白没增加 → 视觉上更挤。

**"中宫宽松" = 同样的字身里留白更多，不是字更大。**

### 2.5 出角过度

参数 `flattenends: 1` + `endsremoval: true` + `hooktension: -0.2` 造成了**全局 45° 斜切**：横画末端、竖画收笔、部件的每个端头都被削成斜角。密集字（圖、圓、曹、鬱、齉）内部笔画糊成一片。

正确的"无出角"是**不额外生出角**，不是**把既有的角磨平**。

### 2.6 拉丁度量失配

| | cap | x-height |
|---|---|---|
| Mona Sans 原版（wght=400） | 729 | 517 |
| 思源黑（应对齐基准） | **733** | 543 |
| **旧版实测** | **784** | **563** |

cap 比中文高 51 单位 → 混排时拉丁永远"跳出来"，压过中文。

另外 `parameters/{ExtraLight..Heavy}.json` 里 7 个文件全写着 `"raleway": N`，**根本没有 Mona 的字段**。说明参数表是 Raleway 时代留下的，Mona 是后面手工换进产物的。参数与产物已脱节。

### 2.7 其他数据缺陷

| 问题 | 数量 | 影响 |
|---|---|---|
| 退化轮廓（面积 < 1 unit²） | 986 | 大字号毛刺，小字号脏点 |
| 内轮廓与外轮廓同向（孔洞被填） | 645（CJK 4E00–9FFF 内） | 结构缺陷 |
| 多轮廓 CJK 字形 | 20702 | — |

## 三、必须继承的教训（写进硬约束）

1. **禁止重新描边。** 形变只能在既有节点上做位移。→ 保证点结构一致，VF 才可能。
2. **禁止裁剪 GSUB 白名单。** 原表原样搬运，只重算数值。
3. **禁止删 cmap 条目。** 删一个码位 = 一个豆腐块。
4. **禁止 GUI 手工修补。** 一切改动进脚本、进 git。不可复现的修补会在下一次迭代里丢失。
5. **"松"不等于"大"。** 中宫调整要在字面率不变的前提下增加负空间。
6. **"无出角"不等于"磨平所有角"。** 直角是有骨，圆角是可爱，斜切是破碎。
7. **拉丁必须以中文为基准对齐度量。** cap 对齐，不能被拉丁的性格带着走。

## 四、值得保留的部分

| 资产 | 价值 |
|---|---|
| 7 档字重的命名与间隔 | 可直接复用（Thin/Light/Normal/Regular/Medium/Bold/Heavy） |
| 目标视觉方向（少出角、中宫宽松、重心适中、宽度适中） | 方向正确，只是执行错了 |
| 对照样张方法（HTML + 截图） | 复用，扩展成自动 QA 闸门 |
| 字重 → 笔画粗细的实测对应关系 | 可作为 stroke_offset 曲线的初值参考 |

实测笔画粗细（"一"的高度 / "丨"的宽度）：

| 字重 | 横画厚 | 竖画宽 | OS/2 |
|---|---|---|---|
| Thin | 34 | 30 | 250 |
| Light | 54 | 52 | 300 |
| Normal | 75 | 73 | 350 |
| Regular | 84 | 83 | 400 |
| Medium | 106 | 105 | 500 |
| Bold | 134 | 133 | 700 |
| Heavy | 162 | 164 | 900 |

> 注意轻端（Thin 34、Light 54）的**跳幅过大**（Light→Normal 只 +21，Thin→Light +20 但基数太小），视觉上 Thin 与 Light 区分不明显，Light 与 Normal 又太近。新方案的 stroke 曲线应该按**视觉感知均匀**排布，参考公式：目标厚度 ≈ 常数 × (wght/400)^0.55。
