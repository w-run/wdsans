## 二、例外：「永」比 OPPO 低 8.5%

我们的「永」钩部转折比方肩，钩尖较短。

但量化后：钩尖相对最低点的位移
```
我们   dx=47 dy=56
Noto   dx=52 dy=65
OPPO   （轮廓合并，无法直接取点）
```

我们比 Noto 的钩短约 10%，但**钩没有消失**。
「永」字面率低 8.5% 主要来自撇捺比 OPPO 收敛（`soften: 0.85` 的作用），不是钩缺失。

## 三、纠正：折角并没有「圆肩」

### 一次视觉误判

我在 260px 放大图上看到「我们的钩转折是方肩、OPPO 是圆肩」，
于是判定 `corner_radius`（规格书标 `❌ 待做`）是真实缺失。

### 测量推翻

统计「口」外轮廓的线段类型：
```
我们   L10 / C0   曲线段 0 条
Noto   L10 / C0   曲线段 0 条
OPPO    L6 / C0   曲线段 0 条
```
直接查角点坐标：
```
我们   右上角是单点 (870, 729)
Noto   右上角是单点 (876.5, 735.4)
OPPO   右上角是单点 (847, 726)
```

**三家都是纯直线、单角点，没有任何一家做曲线圆角。**
我在 PNG 上看到的「圆肩」是 **hb-view 抗锯齿的渲染产物**，不是字形结构。

### 结论

`corner_radius` 不实现是**正确的**，不是缺陷。
规格书把它标成「❌ 待做」是误导——OPPO/鸿蒙/Noto 都没做。
已更正 STROKE-SPEC.md 的状态。
