## 一、tofu-scan：结论正确，附带判断需修正

### 核心结论✓ 采纳

```
检查码位 44,905（format 12）
hb-shape 逐码位 → gid0 = 0 个
实际渲染空白 → 10 个，其中 9 个合法空白字符
排除后空白字形 → 0 个
```

它还做了四道独立验证（uharfbuzz / hb-shape CLI / FreeType 栅格化 / RecordingPen），
并逐个核对了 129 个「空心方框」候选（全是 □▢△▷▽◁◇ 制表符等设计如此字符）。

**这是扎实的工作。**

### U+00AD 的判断✓ 正确

它指出 U+00AD SOFT HYPHEN 渲染空白是 **HarfBuzz 按 UAX #14 的特判**，
字体本身映射到 `hyphen`（有墨），不是缺陷。

我复核确认：这个判断准确。

### 「覆盖缺口」结论 ✗ 需要修正

它报告：
> cmap 缺 U+2000、U+2001、U+2004-U+200A、U+202F、U+205F、U+1680，
> 其中 U+2009 THIN SPACE、U+200A HAIR SPACE、U+202F 是排版常用，
> **属覆盖缺口，建议后续补齐**。

**我复核发现：这些码位在 Noto 里也全部缺失。**

| 码位 | 名称 | 我们 | **Noto** |
|---|---|---|---|
| U+2000 | EN QUAD | 缺 | **缺** |
| U+2001 | EM QUAD | 缺 | **缺** |
| U+2004 | THREE-PER-EM SPACE | 缺 | **缺** |
| U+2005 | FOUR-PER-EM SPACE | 缺 | **缺** |
| U+2006 | SIX-PER-EM SPACE | 缺 | **缺** |
| U+2007 | FIGURE SPACE | 缺 | **缺** |
| U+2008 | PUNCTUATION SPACE | 缺 | **缺** |
| **U+2009** | **THIN SPACE** | 缺 | **缺** |
| **U+200A** | **HAIR SPACE** | 缺 | **缺** |
| **U+202F** | **NARROW NO-BREAK SPACE** | 缺 | **缺** |
| U+205F | MEDIUM MATH SPACE | 缺 | **缺** |
| U+1680 | OGHAM SPACE MARK | 缺 | **缺** |

```
我们空格类总数: 3
Noto 空格类总数: 3    ← 完全相同
```

**这是基座 Noto Sans CJK 的固有覆盖范围，不是我们引入的缺口。**

而且字体无法凭空补码位——P0 铁律：Noto 基座已达 65,535 字形上限
（TrueType 硬上限），**加不了新字形**。

补齐这些空格需要占用现有槽位，代价是删掉某个现有字符，不划算。
浏览器遇到这些字符会回退到系统字体，是正常行为。

**结论修正：不是「待修缺陷」，是「与基座一致的已知边界」。**

## 二、otf-tables：7 项中 1 项真需修（已修）

### A4 命名冲突 ✓ 真缺陷，已修

详见 P67。核心：VF 与静态 Regular 的 name 完全一致，
参照 Mona 上游做法加了 "VF" 后缀。

**修复后验证：**

| 项 | 结果 |
|---|---|
| ID1 | `WDesign Sans VF` ✓ |
| ID6 | `WDesignSansSC-VF` ✓ |
| OTS | **通过（返回码 0）** ✓ |
| wght 轴 | 250-900，默认 400 ✓ |
| 命名实例 | 7 个 ✓ |
| 表数 | 22 ✓ |

### A1/A2/A3 子集裁剪 ✓ 属实，但暂不改

| 项 | 全库 | 子集 | 影响 | 决定 |
|---|---|---|---|---|
| GDEF | 有 | 无 | 无 mark 需求 | 暂不改 |
| GPOS vkrn | 有 | 无 | 竖排西文不 kern | 暂不改 |
| cmap format 14 | 有 | 无 | 无 IVS 需求 | 暂不改 |

理由：子集是 **Web 场景**（中文正文为主），这三项影响极小；
且子集文件才 1.7MB，补回会增大体积。

### A5/A6/A7 已知设计，非缺陷

| 项 | 队友判断 | 复核 |
|---|---|---|
| A5 家族不统一 | 异常 | **P63 已论证**：RIBBI 限制，OPPO/SHS 同做法 |
| A6 VF fsSelection=0 | 异常 | **低影响**：VF 靠 wght 轴标识 |
| A7 无 VF.ttf | 异常 | **交付决策**：50MB 过大 |

## 三、teammate 工具的使用心得

### 有效的地方

**扩大了搜索面**。otf-tables 发现的 A1/A2/A3 三项，
在我的 VERIFICATION-INDEX 里**完全没有覆盖**——
我只查了「表是否存在」，没查「子集裁掉了哪些」。

### 需要注意的地方

**队友会给出「超出其判断权限」的结论**：
- tofu-scan 把「基座固有边界」判为「待修缺口」
- otf-tables 把「P63 已论证的设计」判为「异常」

这两个判断都**缺少必要的上下文**：
- 不知道 Noto 也缺那些空格
- 不知道 RIBBI 约束和 OPPO/SHS 的做法

### 结论：正确的分工

```
teammate：扩大搜索面，找出「可能有问题」的点
lead    ：结合设计意图与参照字体，判定「是否真的是问题」
```

**队友负责「发现」，我负责「定性」。**
两者都需要，但不可互换。
