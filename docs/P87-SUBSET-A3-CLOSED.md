# P87：A3 闭环——P67 三项子集结论全部为「字符集闭包」的正常行为

## 承接 P86

P86 更正了 A1（GDEF）和 A2（GPOS mark/vkrn），但 A3（cmap 子表）留待复核。
本轮闭环。

## 一、format 12 的存留：取决于有无非 BMP 字符

```
仅CJK基本区    子表=2  f4 f4                 fmt14=无
CJK + 非BMP    子表=4  f4 f12 f4 f12        fmt14=无
```

**加入非 BMP 字符后，format 12 自动回来了。**

原因：format 4 只能表示 BMP（≤U+FFFF），有超出的码位就必须用 format 12。
全库有 2,590 个非 BMP 码位，本次测试字符集只有 CJK 基本区，所以 format 12 无事可做。

## 二、format 14（IVS）：需要变体选择符本身在字符集里

第一次测试失败：

```
基字 + 全部 11 个 IVS 基字  →  子表=2  f4 f4   fmt14=无
```

**即使把全部 IVS 基字都放进字符集，format 14 仍然没有。**

### 读源码找到答案

`fontTools.subset` 里 format 14 的处理逻辑：

```python
t.uvsDict = {
    v: [(u, g) for u, g in l
        if g in s.glyphs_requested or u in s.unicodes_requested]
    for v, l in t.uvsDict.items()
    if v in s.unicodes_requested        # ← 关键：变体选择符本身必须在请求集里
}
```

**要保留 IVS 序列，必须把「变体选择符」（U+FE00/FE01）本身放进字符集，
光放基字不够。**

### 验证

```
仅基字              子表=2  f4 f4        fmt14=无
基字 + 变体选择符    子表=3  f4 f14 f4    fmt14=有(19条)
```

**成功保留 19 条变体序列。**

## 三、P67 三项结论的最终裁定

| 项 | P67 结论 | 本轮实测 | 最终判定 |
|---|---|---|---|
| A1 GDEF 丢失 | 属实 | 有组合标记则保留 | **字符集闭包，非缺陷** |
| A2 GPOS 丢 mark/vkrn | 属实，8→6 | GPOS 特性数恒定 5 个 | **字符集闭包，非缺陷** |
| A3 cmap 只剩 2 子表 | 属实 | format 12 需非BMP、format 14 需变体选择符 | **字符集闭包，非缺陷** |

### 共同根因

**三项全部源于同一条机制**：

```
子集工具做「闭包裁减」：
  字符集里没有能触发某个特性/子表的字符
    → 该特性/子表无事可做
    → 自动裁掉（正确行为）
```

| 被裁的东西 | 需要什么才保留 |
|---|---|
| GDEF | 组合标记（U+0300–036F）|
| GPOS mark | 组合标记 + 基字 |
| format 12 | 非 BMP 字符（>U+FFFF）|
| format 14 (IVS) | **变体选择符本身**（U+FE00/FE01）|

## 四、当前交付物是否需要改

### 不需要

| 子集文件 | 用途 | 需要 GDEF/IVS 吗 |
|---|---|---|
| sub3755 / sub6763 | 中文正文 Web | **不需要** |

子集是给中文正文用的。中文正文不含组合标记、不含 IVS、不含非 BMP 字符，
所以这些表「不在」是**恰好正确**的——它们本来也用不上。

### 但如果将来有这些需求，做法已明确

| 需求 | 字符集必须显式包含 |
|---|---|
| 带重音拉丁（café）| U+0300–036F 组合标记 |
| IVS 异体字 | U+FE00–FE0F 变体选择符 |
| Emoji/生僻字（非BMP）| 对应码位本身 |

**这是一份可直接用的操作清单**，已替代「暂不改」这个模糊结论。

## 五、这一轮的方法价值

### 从「暂不改」到「明确知道怎么改」

P67 的结论是：

> 「子集丢了 GDEF/mark/vkrn/IVS，**暂不改**（中文正文影响小）」

这是**基于影响大小的取舍**，但留下了两个隐患：

1. 不知道「要改该怎么改」
2. 把它记成了「缺陷」，实际不是

本轮的结论是：

> 「这些表**本就不该有**（字符集不需要它们）。
> 若将来需要，在字符集里加入对应码位即可。」

**从「记录缺陷」变成「记录机制 + 操作清单」。**

### 三次控制变量，三次推翻假设

```
假设1「GDEF 被工具裁掉」  → 加组合标记，GDEF 出现  → 推翻
假设2「IVS 基字够了」      → 基字全放还是无 fmt14  → 推翻
假设3「源码说要看 vs」     → 加 U+FE00/FE01，出现 → 证实
```

**如果不读源码，假设 2 会被当成「format 14 确实无法保留」的最终结论。**

这正是 METHOD-TRAPS 一直强调的：**「工具不支持」和「我调用方式不对」要分开**。

## 六、教训

### 1. 子集相关的所有「丢失」都要先问「谁需要它」

```
表/特性不存在
  ├─ 字符集里没有需要它的字符  → 正常（本轮 3 项都属此类）
  └─ 字符集里有但被裁了      → 真缺陷
```

**区分方法：构造一个「有需要它的字符」的字符集，看它是否出现。**

### 2. 读源码比猜参数快

尝试多次参数组合都失败后，直接 `inspect.getsource(fontTools.subset)`
看 format 14 的处理逻辑，一步定位到「变体选择符本身必须在请求集里」。

**当 API 文档不足以解释行为时，源码是唯一权威。**

### 3. 这是第三次更正自己的历史结论

| 轮次 | 更正了什么 | 共同模式 |
|---|---|---|
| P79 | P78「槽位为 0」| 观察对，归因错 |
| P86 | P67「子集丢特性」| 观察对，归因错 |
| P87 | P67 的 A3 项 | 观察对，归因错 |

**三次都是：观测到的现象是真实的，但把它归因为「缺陷/限制」是错的。**

这提示一条通用方法：

> **看到异常时，先假设「可能是我的测试方法导致的」，
> 用控制变量排除，再判定是否为缺陷。**
