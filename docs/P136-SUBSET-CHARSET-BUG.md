# P136 · 子集的严重缺陷：字符集取错

日期：2026-11-07
状态：**已修复**。

## 缺陷

我之前生成子集用的是「从 U+4E00 起按码位顺序取 n 个汉字」：

```python
def cjk(n):
    out = []
    for cp in range(0x4E00, 0x9FA6):
        out.append(cp)
        if len(out) >= n: break
    return out
```

**这和「3755 个常用字」完全不是一回事。**

实测后果：

```
sub3755 常用字缺失: 我、的、是
sub6763 常用字缺失: 的
```

「我」「的」「是」是最高频的三个汉字，缺任何一个子集都不可用。

按码位顺序取字，取到的是 Unicode 码位最小的 3755 个汉字，
其中大量是生僻字，而常用字散布在整个区间。

## 正确做法

「3755 / 6763」指 **GB2312 字符集**：

- 3755 = 一级汉字（区位 16-55）
- 6763 = 一级 + 二级汉字（区位 16-87）

```python
def gb2312_level(level):
    out = []
    qs = range(16,56) if level==1 else range(16,88)
    for q in qs:
        for w in range(1,95):
            try: ch = bytes([0xA0+q, 0xA0+w]).decode("gb2312")
            except Exception: continue
            if len(ch)==1 and 0x4E00 <= ord(ch) <= 0x9FA6:
                out.append(ch)
    return out
```

## 教训

**「3755 个常用字」是一个标准字符集的简称，不是一个数量。**

凡是看到「N 个常用字」「N 个汉字」这类说法，
必须先确认它对应哪个字符集（GB2312 / GBK / GB18030 / 通用规范汉字表），
不能自行用「取前 N 个」代替。

这个缺陷我差点没发现——因为文件能生成、能通过 OTS、
渲染个别字也正常。**只有做「常用字覆盖率」抽检才暴露。**
