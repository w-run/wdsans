## 三、六项笔画风格指标

508 字 × 4 字体实测：

```
字体    比例W/H    中宫%   重心    撇捺展开60/70/80     折角°
我们    360/360   34.1   0.501   0.655/0.665/0.659   90.0
SHS     361/361   34.3   0.499   0.661/0.663/0.663   90.0
OPPO    358/366   31.1   0.501   0.633/0.648/0.652   90.0
HOS     358/359   37.2   0.499   0.664/0.684/0.678   90.0
```

| 指标 | 结论 |
|---|---|
| 重心 | 0.501，与 SHS 0.499 / OPPO 0.501 一致 |
| 中宫 | 34.1%，与 SHS 34.3% 一致 |
| 比例 | 360/360，与 SHS 361/361 一致 |
| 撇捺曲率 | 0.655/0.665/0.659，与 SHS 差 ±0.006 |
| 折角 | 90.0°，四家完全一致（只统计两侧都是 L 段的真实直角）|
| 笔末切角 | 0.0，我们 41 处横笔端面全部精确垂直 |

喇叭口不存在：三家参考字体都是均匀笔画，实测竖笔与横笔宽度恒定。

## 四、字形覆盖

```
cmap          45,012  （SHS 44,853，多 159）
CJK           20,992
常用字         508 字零缺失
Latin Ext-A   125/128  （SHS 仅 30/128）
```

所有 Unicode 区块覆盖均 ≥ SHS 基座。

与 OPPO/HOS 相比有 218 个字符缺口，全部无法合规补齐：
这些字符 SHS 也没有，Mona 可供仅 1 个，属于 OPPO/HOS 的扩展字符集，
取用会违反其许可。主要缺口在 Cyrillic(63)、Greek(27)、Gen Punct(23)、Currency(15)。

## 五、已修复的具体缺陷

| 问题 | 规模 | 方法 |
|---|---|---|
| 闭口偏旁被压扁且上移 | 1,040 字 | 顶边固定、底边下移约 80 单位（按字重缩放）|
| 左偏旁底部出脚 | 11 字 | 竖条下端对齐方框底缘 |
| 出类字右下伸脚 | 7 字 | 底横右端贴竖左缘、右竖端与横下缘齐平 |
| 永字竖弯钩台阶 | 全库 20,479 字 | 闭合轮廓末点贴回起点（缝隙 97,121 → 0）|
| 眼字艮部撇尖刺 | 11 字 | 端点 y 回落到平口高度 |
| 数字 9 偏细 | 1 字形 | 从 Mona 取字形（面积小 14% → 一致）|
| 拉丁过窄 5.7% | 486 字形 | 反向缩放 1.0604 恢复 Mona 宽度 |

## 六、未实现项

横折出头（顶部横笔右端延伸）
三轮自动判据（纯轮廓几何法）均误伤左侧偏旁的横笔，最大一次误伤 1,456 / 20,992 字。
已放弃自动方案，当前继承思源黑体的原始形态。
若重做需建立部件级分割，或改为逐字白名单。

横折撇偏粗（多、及、予 等字）
250 档撇厚 38 vs SHS 28（+10 单位 ≈ 1% em，正文与海报字号不可见）。
根因：m_barple 把横笔右端拉到 770 而 SHS 只到 722 —— 这是拐角竖直
这个设计目标的固有代价，二者不可兼得。

已试过三条路径并全部证伪：
1. 事后补丁（m_c2lift）：判据无法区分「多」与「水」，两者几何完全同构
2. IDS 部件分割：IDS 只描述结构树，不描述轮廓归属，无法还原
3. 重建链：实测 250 档改善 5、400 档持平、900 档恶化 10，三档方向不一致


   功能虚报检测（黑名单正则）、HTML 结构配平

- 三档操作符签名一致性：全库 20,992 字，不一致必须为 0
- VF 构建成功（41.3 MB，约 314 秒）
- 改动爆炸半径：实际改动字数 = 索引字数，拓扑改变 0
