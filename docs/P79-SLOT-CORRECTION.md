# P79：更正 P78——槽位「看似可回收」实为不可回收

## 起因

P78 结论是「字形槽位为 0，无法补 tnum」。
但我随即想到：P30 曾用过「回收孤儿字形槽位」的方法。

**于是本轮去核实——结果发现 P78 的论证不充分。**

## 一、第一轮核实：确实有大量「未映射」字形

```
字形总数:          65535
cmap 映射:         44395
未被 cmap 映射:    21140    ← 看起来槽位充足
```

**这直接动摇了 P78 的结论。**

## 二、第二轮：排除特性引用

这些字形可能被 GSUB/GPOS/GDEF 引用，不能动：

```
GSUB/GPOS/GDEF 引用的字形:  12547
真正空闲（无 cmap 也无特性引用）:  10038
```

仍有 **10,038 个**看起来可用。

## 三、第三轮：排除 IVS

```
cmap format 14 (IVS) 引用:  11
且未被 IVS 引用:           21132
```

## 四、第四轮：排除复合部件

```
被复合字形引用的部件数:  0      ← P7 已把复合全部内联
真正可回收槽位:      10037
```

**到这里，「10,037 个可回收槽位」看起来成立。**

如果就此收工，我会得出与 P78 相反的结论：
「槽位充足，可以补 tnum」。

## 五、第五轮：这些字形到底是什么

抽查 bbox：

```
glyph03580  x[ 68, 955] y[-74, 834]   887x908
glyph03592  x[ 68, 951] y[-75, 846]   883x921
glyph03600  x[ 68, 953] y[-76, 835]   885x911
glyph03963  x[ 32, 966] y[-73, 835]   934x908
```

**全部是 ~900×900、y 从 −74 到 834 的标准汉字尺寸。**

不是空白、不是装饰符号、不是占位——**是一个个真实的汉字**。

## 六、决定性检查：它们是否与已映射字形重复

如果它们是「同一个字的重复副本」，回收无害。
如果不是，就是独立字形。

用轮廓坐标做指纹比对：

```
候选字形:                  21139
已映射字形的不同指纹数:    44375
抽 300 个候选:
  与已映射字形重复:            0
  独有:                      300
```

**300 个样本，0 个重复——全部是独有字形。**

## 七、结论：P78 结论正确，但理由不完整

| 检查项 | 结果 |
|---|---|
| 未映射字形 | 21,140 |
| 减去特性引用后 | 10,038 |
| 减去 IVS 后 | 10,037 |
| **但这些是** | **独立汉字字形（异体/竖排变体）** |
| 与已映射字形重复率 | **0/300** |
| 可否回收 | **不可**（会丢失基座的潜在字形覆盖）|

### 为什么它们没进 cmap

Noto Sans CJK 的 cmap 只映射**标准字形**。
另有大量**异体字、竖排变体、地区变体**存在于 glyf 表中，
但通过 IVS 或特定排版语境访问，不在默认 cmap 里。

**它们是基座设计的一部分，不是冗余。**

## 八、这次核查的价值

### 1. P78 的结论没变，但依据从「槽位为 0」修正为「槽位不可回收」

原结论：
> 字形数 65535 = 上限，剩余槽位 0，无法补 tnum

**这个论证是错的**——实际有 10,037 个未引用槽位。

修正后：
> 有 10,037 个未引用槽位，但每一个都是独立汉字字形（异体/竖排变体），
> 回收会丢失基座覆盖，**等同违反「不删字形」铁律**。

**结论相同，但理由完全不同。**

### 2. 「看似可用」需要四层验证才能下结论

本轮做了五轮：

| 轮次 | 检查 | 结果 |
|---|---|---|
| 1 | cmap 映射 | 21140 未映射 |
| 2 | GSUB/GPOS/GDEF | 10038 |
| 3 | cmap format 14 (IVS) | 10037 |
| 4 | glyf 复合部件 | 10037（部件引用 0）|
| **5** | **与已映射字形是否重复** | **0/300 重复 → 不可回收** |

**前四轮都指向「可回收」，第五轮才推翻。**

如果只做前四轮就下结论，会得出错误的修复方案。

### 3. 这次是「推翻自己」，而不是「推翻别人」

P78 是我写的，P79 也是我写的。
**发现自己上一轮的结论论证有漏洞，就该回头补查。**

不是「结论对了就不用查」——P78 结论确实是对的，
但**依据错了**。依据错意味着：如果条件变化（比如找到真正冗余的字形），
我会因为「槽位为 0」这个错误前提而错判。

## 九、最终结论

| 项 | 结果 |
|---|---|
| tnum 能否补 | **否** |
| 原依据（槽位 0）| **错误**，实际有 10,037 未引用槽位 |
| 正确依据 | 那些槽位全是**独立汉字字形**，回收即违反铁律 |
| 与 P30 的差异 | P30 回收的是「拉丁合并留下的孤儿」（真冗余），**性质不同** |

### 与 P30 的关键区别

P30 回收的是什么？——**拉丁合并时被覆盖的原字形**，
它们的内容已无任何途径访问，是**真冗余**。

本轮这些呢？——**基座原有的汉字变体**，内容有意义，只是不在默认 cmap。

**「无引用」不等于「无价值」。**
