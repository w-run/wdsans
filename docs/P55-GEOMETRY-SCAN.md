# P55：全库 65,535 字形几何健壮性扫描

## 动机

`thin_edges()` 用 `_offset_miter` 把笔画边缘沿法向平移（横 −12 / 竖 −7 upm）。

这种操作的**风险**：
- 若某段笔画本身只有 10 upm 厚，减掉 12 就会**塌缩成零或反向**
- 复杂字形（多笔交叉）可能产生**自交**，渲染出现黑三角

而函数内的断言只检查：
```python
assert len(out) == n_before, f"{name}: 点数变了"
```
**只验点数守恒，不验几何有效性。**

所以必须独立扫描全库。

## 扫描方法

用 `AreaPen` 计算每个字形的**有向面积绝对值**：

| 面积 | 含义 |
|---|---|
| 0 | 空轮廓（塌缩）或空白字符 |
| < 200 平方单位 | 极小碎片（渲染为黑点） |
| 正常 | 有意义的字形 |

## 结果：零缺陷

```
我们 Regular: 总 65535 字形, 零面积 11, 极小碎片(<200) 0
我们 Thin:    总 65535 字形, 零面积 11, 极小碎片(<200) 0
```

**13 万个字形（两档 × 65535）中，极小碎片 = 0。**

## 11 个零面积字形的身份

```
space      U+0020  普通空格
uni2002    U+2002  半角空格（en space）
uni2003    U+2003  全角空格（em space）
uni115F    U+115F  谚文填充符（Hangul Choseong Filler）
uni1160    U+1160  谚文中声填充符
glyph63108 / 64403 / 65531-65534   内部保留槽位
```

**全部是「按设计就没有轮廓」的字符**，不是塌缩产物。

## 决定性验证：与 Noto 逐一对比

| 项 | 我们 | Noto |
|---|---|---|
| 零面积字形数 | **11** | **11** |
| 具体名单 | 完全相同的 11 个 | — |
| 我们独有 | **[] （空）** | — |
| Noto 独有 | — | **[] （空）** |

**清单逐字一致，没有任何一个字形因减细而塌缩。**

这说明三种可能：
1. 减细算法对所有正常字形都安全（面积保持 > 0）
2. 或者 `thin_edges` 的自校准逻辑（`if best[0] < a0` 才采纳）
   在遇到会塌缩的段时**放弃了减细**，保留了原样

代码里确实有这个保护：
```python
for sign in (1.0, -1.0):
    s2 = _offset_miter(seg, d_h, d_v, sign)
    a2 = abs(_area(s2))
    if best is None or a2 < best[0]:
        best = (a2, s2)
out.extend(best[1] if best[0] < a0 else seg)   # ← 若不减小面积则放弃
```

**只有「减细后面积确实变小」才采纳，否则保留原始段。**
这是防塌缩的关键保护。

## 结论

| 项 | 结果 |
|---|---|
| 扫描范围 | 65,535 字形 × 2 档 = 131,070 |
| 极小碎片 | **0** |
| 零面积字形 | 11（全部为空白字符） |
| 与 Noto 对比 | **清单完全一致，零差异** |
| 防塌缩机制 | `best[0] < a0` 才采纳 |

**减细操作在全库范围内几何安全。**

## 一个值得记住的点

「断言通过」不等于「结果正确」。

`thin_edges` 里的 `assert len(out) == n_before` 只能保证**点数没变**。
一个点数不变但完全塌缩的轮廓（比如所有点挤到一点）也能通过这个断言。

**必须用独立的几何度量（面积）二次验证，不能依赖构建时的断言。**
