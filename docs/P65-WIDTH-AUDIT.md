# P65：字符宽度分布审计

## 动机

拉丁来自 Mona、中文来自 Noto，两者合并后**宽度体系是否冲突**？
若拉丁字符被误设为全角（1000），混排时会出现大片空白；
若中文字符被误设为比例宽（非 1000），排版会错位。

## 一、宽度分布（44,905 码位）

| 宽度 | 码位数 | 占比 | 代表性字符 |
|---|---|---|---|
| **1000**（全角）| 32,540 | **72.5%** | 汉字、全角标点 |
| **920** | 11,675 | **26.0%** | U+1100 ᄀ（谚文字母）|
| 500（半角）| 72 | 0.2% | U+02D9 ˙ |
| 其他 249 种 | 618 | 1.4% | 拉丁字母/符号 |

共 **249 种不同宽度值**。

## 二、920 宽度是什么

11,675 个码位（26%）宽度为 920，示例 **U+1100「ᄀ」**（谚文字母）。

这是 **Noto Sans CJK 基座的设计**——韩文谚文字母在 Noto CJK 中就是 920 宽
（比汉字略窄，因为谚文字母通常与汉字混排但视觉体量略小）。

### 与 Noto 逐值对比

| 宽度 | 我们 | Noto | 差 |
|---|---|---|---|
| 1000 | 32540 | 32555 | **−15** |
| **920** | **11675** | **11675** | **+0** |
| 500 | 72 | 72 | **+0** |

**920 和 500 完全一致（差 0）**，说明我们**没有改动基座的宽度体系**。

1000 宽少 15 个，是因为我们把这些码位挪给了拉丁扩展（Latin Ext-A 修复，P30），
那些字符宽度是比例宽而非 1000，属于预期变化。

## 三、宽度 0 的 13 个字符

```
U+0300 ̀  gravecomb      （组合重音）
U+0301 ́  acutecomb      （组合重音）
U+0304 ̄  uni0304        （组合长音）
U+0307 ̇  uni0307        （组合上点）
U+030C ̌  uni030C        （组合抑扬）
U+20DD ⃝  uni20DD        （组合圆圈）
U+20DE ⃞  uni20DE        （组合方框）
U+302A 〪 uni302A        （声调符）
U+302B 〫 uni302B        （声调符）
...
```

**全部是组合标记（combining marks）**。

Unicode 规定：组合标记的 advance width **必须为 0**，
因为它要叠加在前一个字符上，不占独立宽度。

**这是正确设计，不是缺陷。**

## 四、关键验证：中文字符是否都是全角

| 检查项 | 结果 |
|---|---|
| 常用汉字（CJK Unified U+4E00-9FFF）| 全部 1000 宽 ✓ |
| 全角标点（U+3000-303F）| 1000 宽（除声调符）✓ |
| 拉丁字母（U+0041-007A）| 比例宽 ✓ |
| 组合标记 | 0 宽 ✓ |

**宽度体系正确：中文全角、拉丁比例、组合标记零宽。**

## 五、结论

| 项 | 结果 |
|---|---|
| 宽度种类 | 249 种（正常，拉丁字符各有宽度）|
| 1000 宽（汉字）| 32,540 个，与本项目 CJK 覆盖一致 |
| 920 宽（谚文）| 11,675 个，**与 Noto 完全一致** |
| 500 宽（半角）| 72 个，与 Noto 完全一致 |
| 0 宽（组合标记）| 13 个，Unicode 规定如此 |
| 异常 | **无** |

## 六、教训

**「26% 的字符宽度都是 920」看起来像异常，实际是基座固有设计。**

如果不与 Noto 对比，很容易误判为「宽度体系混乱需要修」。
实测 `920: 11675 vs 11675`（差 0）立刻说明问题不存在。

这是 METHOD-TRAPS 里「对比参照字体」原则的又一次应用。
