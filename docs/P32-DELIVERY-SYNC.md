# P32：交付物完整同步到 w-pc（15/15）

## 问题

上一轮重建后，w-pc 交付物只同步了 1/15，其余仍是旧版。

## 瓶颈

实测网络吞吐 **0.08 MB/s**，220MB 需约 45 分钟。
ssh 通道单文件传输约 100s/20MB，一轮工作窗口只能传 1~2 个。

## 解决：压缩后再传

| 格式 | 压缩率 | 说明 |
|---|---|---|
| TTF + gzip | 20MB -> **11.3MB (57%)** | Node 内置 zlib 可直接解压，无需装工具 |
| TTF + xz | 20MB -> 9.0MB (45%) | 更小，但 w-pc **没装 xz**，弃用 |
| WOFF2 | 7.5MB -> 7.5MB (100%) | 已压缩，无法再压 |

**最终方案**：TTF 走 gzip（省 43% 字节），WOFF2 直传。

## 结果

| 项 | 结果 |
|---|---|
| 文件数 | **16/16 全部同步** |
| 总体积 | 220.4 MB |
| TTF 魔数 | 0x00010000，16 表 |
| WOFF2 魔数 | wOF2 |
| 七档 Latin Ext-A | **125/128** |
| 新字符渲染 | 31/31 正常 |

## 经验

**窄带宽下必须把「压缩」纳入交付流程。**
这次花了一整轮（约 40 分钟）才传完 15 个文件，
如果一开始就用 gzip，能省掉约 17 分钟。

下次在大文件交付前，先测一次吞吐，再决定是否压缩。
