# 用户反馈三项问题诊断（2026-11-19 R45）

## 问题 1：数字 1 偏右 + 字间距无动态调整

### 根因：TTF 转换时坐标被平移，每个字位移量不同
```
OTF 的 lsb 与 bbox.xmin 不一致（87% 字形如此）:
  1  lsb=95  xmin=26   差 69
  0  lsb=55  xmin=79   差 -24
  A  lsb=11  xmin=32   差 -21
  永 lsb=44  xmin=37   差 7

TrueType 要求 lsb == xmin。我之前的转换为了满足这个约束，
在 save 时被 fontTools 自动平移坐标 -> 每个字平移量 = lsb - xmin
-> 字形相对位置全乱，数字 1 右移 69 单位，字距看起来不对。

🔴 关键认知: CFF 里 lsb 不参与渲染定位，坐标才是绝对位置。
   所以「坐标不动、改 lsb」才是正确做法。

✅ 修复: save 前遍历所有字形，把 hmtx.lsb 改成实际 glyf.xMin
   坐标完全不动。验证:
     构造时首点 (201,540) -> 保存后首点 (201,540)  坐标保住
     1 bbox=(26,0,295,730) 与 OTF 完全一致（原 TTF 是 95,364）
     0 bbox=(79,-11,558,738) 一致（原 55,534）
     A bbox=(32,0,667,729) 一致（原 11,646）
   校正规模: 250档 5454 / 400档 64781 / 900档 64968 个字形
```

### 字间距「无动态调整」
```
实测 kerning 是生效的:
  AV  kern=603  nokern=697  有调整
  To  kern=487  nokern=644  有调整
  LT  kern=359  nokern=579  有调整
  12  kern=544  nokern=544  无调整（数字对之间本就没有 kern 对）

-> 拉丁 kern 正常。「间距不对」的观感来自上面的坐标平移问题。
```

## 问题 2：捺笔变细、端面平切效果差（R41/R42 方向错误）

### 用户判断准确，R41 的整个方向是错的
```
R41/R42 的 m_vertend 把捺笔末端的 C（曲线）换成 L（直线）:
  人 c1[2]:  R37 C 长84  ->  R42 L 长64
  大 c1[2]:  R37 C 长89  ->  R42 L 长69
  天 c0[2]:  R37 C 长86  ->  R42 L 长68
  夫 c2[2]:  R37 C 长85  ->  R42 L 长70
  文 c1[2]:  R37 C 长87  ->  R42 L 长70
去掉一个控制点 -> 笔画变细，正是用户说的「捺被改坏了」

### 决定性证据：参考字体根本没有垂直平切
捺笔末端「最右处垂直跨度」（越小越平）:
  字   SHS  OPPO  HOS  我们R37  我们R42
  人     8    11    13        8       92   <- 拉长 11 倍
  大     8    11    13        7       99
  天     8    12    14        8       96
  夫     7    16    15        9       99
  文     7    17    17        8       98
  父     7    15    14        7      107
  久     9    14    14        8       97

OPPO/HOS 的端面跨度只有 11-17，和 SHS 的 7-9 基本一致。
R41 把端面从 8 拉到 92，造出了明显的方头。

段类型序列印证:
  人 SHS  LCCCCCCC
  人 OPPO QQQLLQQLQQQQ   <- 末端仍是曲线
  人 HOS  LQQLQQLLQQ      <- 末端仍是曲线

### 结论: R41/R42 的 m_vertend 应完全回退
从 masters_R37 重建（不跑 m_vertend），其余后处理照常。
```

## 问题 3：睛 类字偏旁拉长但内部笔画没跟上

### 根因：R33 的 m_boxrad 在拉长偏旁时丢掉了一条内横
```
睛的左「目」旁内横:
  SHS:  3 条  y=[573,711] [365,508] [153,300]  间距均匀
  R33:  2 条  y=334, 542                       <- 少了最上面一条
  R37:  2 条（继承 R33 的问题）
  R42:  2 条

m_boxrad 只把外框向下延伸（BOTTOM_EXTEND 35/80/152），
没有同步移动/保留顶部内横 -> 内部笔画全挤在上半部。
这正是用户说的「内部笔画没变、太靠上了视觉效果很差」。
```

## 已确认的教训
```
1. 「垂直平切」是我自己发明的目标，不是参考字体的特征。
   做笔画风格调整前必须先在参考字体上验证该特征真实存在。
   我把端面从 8 拉到 92，而 OPPO 只有 11-17。

2. CFF 的 lsb 不参与渲染。转 TTF 时改 lsb 保住坐标，
   而不是平移坐标去迁就 lsb。

3. 用户的三次反馈（字重丢失 / 捺笔变细 / 偏旁内部笔画）
   全部准确，而我的自测都没发现。验证样本必须覆盖用户视角。
```
