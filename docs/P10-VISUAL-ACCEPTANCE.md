## 真实正文样张（不是单字形，是排版实况）

用 WDesignSansSC-Regular.ttf 渲染 12px / 16px / 24px / 40px 四档：
- 12px：中文正文混 ABC 缩写与百分比，字形清晰、标点正常、无豆腐
- 16px：中英混排 + 全字母表 + 数字串，字距均匀、无粘连
- 24px：标题行，中英混排基线对齐
- 40px：大字预览，带重音拉丁 ÁáÉé 与中文、数字并列正常

## 一处自我纠错（重要）

第一次看 12px/16px 样张时，我的判断是：
  「Mona 拉丁 x-height 明显小于中文，混排时拉丁显得偏小偏弱」。

**这个判断是错的。** 用像素标尺实测（font-size=200，取墨迹上下界）：

| 字 | 合并后 | 合并前(Noto) | 比值 |
|---|---|---|---|
| x | 106 | 107 | 0.991 |
| n | 108 | 108 | 1.000 |
| o | 110 | 109 | 1.009 |
| H | 147 | 145 | 1.014 |
| 国 | 173 | 173 | 1.000 |
| 口 | 156 | 156 | 1.000 |

x-height / 中文「国」的比值：合并前 0.618 → 合并后 0.613，**差 0.8%**。

结论：x-height 与中文的比例几乎没变（0.8% 在印刷上不可辨），
「明显偏小」是错觉。中文侧完全未动（国/口 像素高度一模一样）。

## 又一次印证

这是本项目第 **八** 个「凭眼睛判断、被测量推翻」的案例：
1. gvar delta 编辑能改默认实例
2. 等比缩放能改墨密度
3. 出脚 = 低于基线
4. 出脚 = 细竖顶出头
5. 出脚 = 轮廓间关系（实为轮廓内 ⊓ 开口）
6. 折角微圆 8-14u 存在
7. 竖/横比目标 1.074
8. 拉丁 x-height 明显偏小  <- 本次

前七个是推理错，第八个是「看图后仍判断错」，更值得记：
**看图能发现「哪里别扭」，但判断「别扭的原因和幅度」仍需标尺。**
