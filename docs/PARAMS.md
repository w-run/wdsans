# 参数体系：旧版诊断 → 新版目标

> **参照方：HarmonyOS Sans SC + OPPO Sans。基座：思源黑体 2.005。**
> glow-sans 只作算法参考，**绝不作风格参考** —— 我们与它风格差距很大。
>
> 对照对象：`/var/minis/shared/wdsans202506/*.json`（旧版 7 档）。
> 版本：v1.1 · 2026-10-22

## 一、旧版参数逐项判决

> **重要更正（2026-10-22，用户纠正）**：`softness 0.85`、`hooktension`、出脚去除、笔末平直化 **都是确认的设计方向**，不是参数填错。
> 下面表格里的"❌"只表示**与 glow 官方默认值的偏差**，不表示方向错误。真正的判据是视觉效果。

| 参数 | 旧版值 | glow 官方 | 与技术默认的偏差 | 结论 |
|---|---|---|---|---|
| `width` | 1 | 1 | 一致 | ✅ |
| `xtracking` | 1.005 | 0.98 | +2.5% | ⚠️ 待视觉判定 |
| `ytracking` | **1.045** | 1.0 | +4.5% | ⚠️ 与「字面 0.88」冲突，待重设 |
| `counter` | **1.048** | 0.955–0.98 | 反向外扩 | ⚠️ 中宫目标本身要"松"，方向可能对，量需重定 |
| `gravity` | 0.965 | 1.01–1.03 | 反向 | ⚠️ 待视觉判定 |
| `weight` | 1.2 / 1.02 | 0.82–1.08 | — | ⚠️ 细字重加粗过多，破坏阶梯 |
| `softness` | **0.85** | 0.90–0.98 | -0.05 | ✅ **确认方向**（克制、干净） |
| `dotsoftness` | **0.7** | 0.25 | +0.45 | ✅ 确认（点保留原形） |
| `flattenends` | **1.0** | 0.75 | +0.25 | ✅ 确认（笔末平直化，但只作用于端面） |
| `hooktension` | **-0.2** | 0.4–0.7 | 反向 | ✅ **确认要做**，数值需重定（种子 +0.55） |
| `feetremoval` | true | true | 一致 | ✅ 确认（去出角） |
| `endsremoval` | true | true | 一致 | ✅ 确认 |
| `baseline` | 55 | 120 | -65 | ⚠️ 待重定 |
| `latinscale` | 1.15 | 1.08 | +0.07 | ⚠️ 但仍不合中文 cap 733 |
| `shs` | 0–6 | 0–6 | 一致 | ✅ |

### 结论修正

**旧版的方向是对的，坏在"执行质量"和"参数与产物脱节"。**

真正的问题只有两条：

**1. 曲线段被彻底破坏。**
`已` 在 SHS 里有 7 段三次曲线，旧版只剩 4 段二次曲线且形状崩坏；`永` 的 16 段曲线在旧版里被重建成形状错误的二次曲线。
根源是 `光栅化 → 骨架 → 重描边` 这条管线：曲线在光栅化时就被离散化了，重描边时只能拟合出折线。

**2. 参数与产物脱节。**
`weight: 1.2` 应让笔画 +20%，实测 Thin 只有 +3%；`latinscale: 1.15` 实测 1.07。
说明产物在 FontCreator 里被手工改过，JSON 只是"当初的想法"。

## 二、比例失调的实测证据

全字符集对比（CJK 4E00–9FFF，20970 个可比字形，SHS SC Regular @400 vs 旧版 Regular）：

| 指标 | 中位 | 标准差 | P5 | P95 | 极差 |
|---|---|---|---|---|---|
| 宽比 | 0.973 | 0.009 | 0.954 | 0.984 | **0.106** |
| 高比 | 1.001 | 0.008 | 0.982 | 1.005 | **0.123** |

整体看还算整齐（标准差 < 1%），**但极差 12%** —— 问题集中在特定字形上，一旦出现就非常扎眼：

| 字 | SHS 高 | 旧版高 | 高比 | 现象 |
|---|---|---|---|---|
| 口 | 658 | 605 | **0.92** | 方框被压扁 8% |
| 凹 | — | — | **0.93** | 同上 |
| 四 | — | — | **0.93** | 同上 |
| 詹 / 賢 / 霁 | — | — | 宽 0.93 | 宽扁化 |
| 亠 / 宀 / 爫 / 龷 | — | — | 高 **1.04** | 顶部独体部件被拉长 4% |
| 鼎 | — | — | 宽 **1.03** | 变宽 |

按 SHS 原生高度分组：

| SHS 高度段 | 字数 | 宽比中位 | 高比中位 | 高比 P5 | 高比 P95 |
|---|---|---|---|---|---|
| < 700 | 23 | 0.972 | **1.029** | 0.976 | 1.039 |
| 700–820 | 62 | 0.973 | 0.999 | 0.929 | 1.011 |
| 820–880 | 1492 | 0.973 | 0.998 | 0.959 | 1.003 |
| ≥ 880 | 19393 | 0.974 | 1.001 | 0.986 | 1.005 |

**结论**：字身越小的部件被拉得越多（<700 组 +2.9%），中等字面被压（P5 到 0.929）。**"口"这类小方框字和"国"这类大字面字，不再是同一个视觉字号。**

根因：`counterScale`（x 的幂函数）与 `gravityAdjustment`（y 的幂函数）都是**对坐标的全局非线性映射**。同一个函数作用在"点集中在小范围"的部件和"点铺满全字身"的字上，等效缩放不同。**这是全局几何滤镜的固有缺陷，调参救不回来。**

## 三、新版参数体系

### 3.1 原则

1. **参数与产物的唯一真相**：参数 JSON 进 git，产物只能由它生成，禁止手工修补。
2. **一致性优先于表现力**：宁可效果温和，也不能让不同字形之间的比例漂移。
3. **每档字重的参数是一条曲线**，不是七个独立值 —— 只有 `stroke` 允许按档位独立调。
4. **不做全局非线性映射**（`counter`/`gravity` 那种坐标幂函数），改为**部件级位移 + 线性场**。

### 3.2 新版参数 schema

```json
{
  "wght": 400,
  "face":     { "target_w": 880, "target_h": 880 },
  "spread":   { "factor": 1.04, "mode": "component" },
  "gravity":  { "target_center": 512 },
  "stroke":   { "delta": 0 },
  "weights":  { "curve": "perceptual" }
}
```

字段语义：

| 字段 | 含义 | 单位 |
|---|---|---|
| `face.target_w/h` | 字面归一化目标（bbox 宽/高） | 设计单位 /1000 em |
| `spread.factor` | 中宫松散系数（1.04 = 留白 +4%） | 无量纲 |
| `spread.mode` | `component`（部件外推，推荐）/ `radial`（径向，仅对照用） | — |
| `gravity.target_center` | 视觉重心目标 y | 设计单位 |
| `stroke.delta` | 笔画额外加粗/减细 | 设计单位 |

### 3.3 七档目标值

| 字重 | wght | 字面 w×h | 中宫系数 | 重心 y | 笔画增量 |
|---|---|---|---|---|---|
| Thin | 250 | 880×880 | 1.040 | 508 | 0 |
| Light | 300 | 880×880 | 1.040 | 508 | 0 |
| Normal | 350 | 880×880 | 1.040 | 510 | 0 |
| Regular | 400 | 880×880 | 1.035 | 512 | 0 |
| Medium | 500 | 880×880 | 1.030 | 512 | 0 |
| Bold | 700 | 880×880 | 1.025 | 516 | 0 |
| Heavy | 900 | 880×880 | 1.020 | 516 | 0 |

> 粗字重中宫系数递减：笔画变粗后留白本来就被压缩，不能再往外推，否则会撞部件。

### 3.4 笔画粗细：用「视觉等距」而不是照抄 SHS

SHS 原生厚度（实测「一」的字高）：

```
250:33  300:53  350:73  400:82  500:104  700:131  900:159
```

问题：**350→400 只差 9 单位**（而 300→350 差 20）。这导致 Normal 和 Regular 几乎无法区分。

新版目标（等比级数，七档感知均匀）：

```
t(k) = 33 × (160/33)^(k/6),  k = 0..6
→ 33, 43, 56, 73, 95, 123, 160
```

对应 `stroke.delta`（相对 SHS 原生）：

| 字重 | SHS 原生 | 新版目标 | delta |
|---|---|---|---|
| 250 | 33 | 33 | **0** |
| 300 | 53 | 43 | **-10** |
| 350 | 73 | 56 | **-17** |
| 400 | 82 | 73 | **-9** |
| 500 | 104 | 95 | **-9** |
| 700 | 131 | 123 | **-8** |
| 900 | 159 | 160 | **+1** |

> 减细比加粗安全：向内收缩不会产生自交，加粗才容易撞部件。
> **Thin 和 Heavy 保持原生** —— 用户明确要极细极粗用于大字标题。

## 四、缺失的算子（当前状态）

用户问的三件事，现状如下：

| 能力 | glow-sans | 新版 | 状态 |
|---|---|---|---|
| 笔画软硬 | `soften(factor)` 控制点向 on 点收缩 | `soften(tension)` in `transforms.py` | ✅ 已实现（需视觉验收） |
| 中宫/重心/字面 | 非线性全局映射 | `spread` / `gravity` / `face` | ✅ 已实现 |
| 笔画粗细 | `weightAdjustment` | `stroke` | 🟡 有实现，未验证 |
| 去出角（feet removal） | `removeFeet()`，检测「脚」并削掉 | 无 | ❌ 待实现 |
| 端点平切 | `strokeEndsFlatten(ratio)` | 无 | ❌ 待实现 |
| 钩张力 | `hookTension(ratio)` 横钩向中心收 | 无 | ❌ 待实现 |
| 点柔化 | `softenDots(value)` | 无 | ❌ 待实现 |

**当前状态：7 个算子中 3 个可用，4 个笔画级细节算子缺失。**

### 实现计划（按性价比排序）

1. ~~`soften`（笔画软硬）~~ ✅ 已完成 —— 只需把控制点向两端 on 点的连线收缩一个比例，不涉及检测，风险最低。
2. **`hooktension`（钩张力）** — 检测条件简单（三点共线的横向短段），只改两个 x 坐标。**这是最该补的一个**：旧版给了 -0.2，把钩反向张开，是「怪」的第二大来源。
3. **`strokeEndsFlatten`（端点平切）** — 需要端点检测（连续 off/on 交替 + 两端距离 < 1.4×笔画宽）。
4. **`removeFeet`（去出角）** — 最复杂，7 点检测 + 削掉后要处理索引更新。glow 的实现是**删点**，我们必须改成**移动点**否则破坏 VF 一致性。
5. **`softenDots`** — 简单但收益小，放最后。

> ⚠️ 第 4 项是难点：glow 删点后重建轮廓，点结构必然变化。我们必须把"删掉脚"改成"把脚的两个点收拢到肩上"，保持点数不变。

### 关于「去喇叭口凹进」

需要先说清一件事：**思源黑是黑体，本身没有宋体那种喇叭口**。它有的是：

- **出角（脚）**：竖画顶端、部件竖起处的小方突，`removeFeet` 处理的就是这个
- **转角凹进**：横竖交接处的内凹小缺口

这两者都需要**局部几何识别**，不是全局滤镜能做的。旧版靠 `flattenends: 1` 一刀切，结果把所有端点都削平了——包括不该动的。

新版的做法：先做**节点角色分类**（端点 / 转折 / 钩 / 脚 / 交点），再按角色分别处理。这是 P1 的核心工作量。

## 五、验收标准（每次改参数都要过）

1. **比例一致性**：抽样 300 字，字面宽/高的标准差 < 2%（旧版是 8%）
2. **字重可分辨**：相邻档位的笔画厚度差 ≥ 8%（旧版 350↔400 只有 12%，且视觉不可辨）
3. **无破形**：轮廓自交 = 0，退化轮廓 = 0
4. **视觉复查**：必须出图并实际看过（见 PIPELINE.md §5.5 铁律）
