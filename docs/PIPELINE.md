## 0. 核心命题

**在保住可变字体与 OpenType 特性的前提下，改造思源黑的视觉风格。**

这一句话决定了全部技术选择。凡是会破坏"节点一一对应"或"表结构完整性"的做法，一律否决——包括 glow-sans 的整套建模方式。

## 2. 为什么必须是"节点位移"

| | 重建轮廓（glow-sans） | 节点位移（本项目） |
|---|---|---|
| 点结构 | 每字重独立漂移 | **所有 master 完全一致** |
| 可变字体 | 不可能 | 天然成立 |
| GSUB/GPOS | 手工重建，只能拿白名单 | 原表不动 |
| 曲线质量 | 光栅化+重描边，误差累积 | 只在原曲线上移动节点 |
| 可复现 | 依赖 GUI 手工修补 | 全脚本，可 git diff |

**实测反例**：旧版 Regular↔Thin 点结构兼容率 **6.1%**（1958/31914），Regular↔Heavy **4.8%**（1520/31914）——插值在数学上不成立。这就是"无法生成可变字体"的全部原因。

## 3. 形变模型

### 3.1 输入表示

不做"骨架 + 厚度"的逆向建模（那是 glow 的路，需要光栅化，误差大且不可逆）。改用**直接作用于轮廓节点的坐标场**：

```python
# 每个节点有：坐标 (x, y)、类型（on/off）、所属轮廓、所属部件
# 每个变换是一个纯函数：Point -> Point
# 组合方式：f(g(h(p)))
```

关键约束：**变换前后节点数量、顺序、类型完全相同**。这条约束要写进代码断言。

### 3.2 四个算子

| 算子 | 作用 | 数学 | 影响指标 |
|---|---|---|---|
| `component_spread` | 部件外推 / 内缩 | 部件质心 + (p - 质心) × k，k 与部件到字心距离相关 | 中宫负空间、结构间隙 |
| `gravity_warp` | 重心调整 | 沿 y 的分段映射，保持基线与字顶不动 | 视觉重心 |
| `stroke_offset` | 笔画粗细 | 沿节点法线偏移，位移量 ∝ 该点所属笔画的局部宽度 | 字重、对比度 |
| `end_shape` | 端点处理 | 仅在判定为 stroke end 的节点上，沿切线/法线移动 | 出角、撇捺钝化 |

`end_shape` 是唯一"可能改变视觉效果很多但不动点数"的算子——只在已有节点上做沿边缘的移动，把 45° 斜切改成平切，把针尖改成钝头。

### 3.3 部件识别

避免逐字手写规则。流程：

1. 用轮廓的**连通性与拓扑关系**做粗分割（CJK 字形天然是"笔画组"）
2. 用笔画方向直方��归类（横/竖/撇/捺/折/钩/点）
3. 结果存为 JSON（`build/components/<gid>.json`），**人类可读、可 diff、可 git 管理**

不做全自动：允许人工覆盖，覆盖记录也进 git。

## 4. 可变字体构造

### 4.1 路线

```
SHS VF (CFF2)
   │  instancer: 7 个 master（250/300/350/400/500/700/900）
   ▼
7 × 静态轮廓（点结构必然一致，因为来自同一 VF）
   │  应用四个算子（同一函数，同一参数曲线）
   ▼
7 × 变形后的静态轮廓
   │  fontTools.varLib.cff merge（CFF→CFF2 blends）
   ▼
wdsans-vf.otf
```

**为什么先实例化再合并**：fontTools 直接编辑 CFF2 的 blend 运算支持很弱；而 `varLib.cff` 本来就是 ufo2ft 用来生成 CFF2 的路径，成熟可靠。先降维成静态、再升维回去，损失为零（在 master 位置插值是精确的）。

### 4.2 拉丁合并

Mona Sans VF 在**源层**改度量（`.glyphspackage` + `build.ninja`），重新 build 后与中文字体做 cmap/GPOS 合并。

若源层构建在本机不可行（需要 Glyphs 生态），退路：
1. 实例化 Mona VF → 按 `733/729` 统一缩放 → 直接合并轮廓
2. 合并后手工修 `OS/2` 度量与 `kern`

### 4.3 特性表处理

**不重建。** 具体动作只有三类：

1. **保持**：GSUB / GPOS / GDEF / BASE 原样搬运
2. **重算数值**：`kern` 成对值、`palt`/`halt` 的 advance 调整、mark 锚点、`vmtx`
3. **更新度量**：`OS/2` 的 xHeight/capHeight、`hhea`、`CFF Private` 的 `StdHW`/`StdVW`/`BlueValues`

**铁律：**
- 不得删 cmap 条目
- 不得裁剪 GSUB feature 白名单
- 不得只保留 `DFLT` 一个 script（`hani`/`kana` 的语言特性要留）

## 5. 质量闸门（QA Gates）

每一轮构建必须全部通过，否则不允许出样张。**没有闸门，AI 驱动的迭代会变成无限修字。**

### 5.1 结构闸门

| 检查 | 阈值 |
|---|---|
| 轮廓自交 | **0** |
| 退化轮廓（面积 < 1 unit²） | **0** |
| 孔洞方向错误（内轮廓与外轮廓同向） | **0** |
| bbox 超出 `[-50, 950] × [-150, 950]` | **0** |
| 变形后节点数与 master 不一致 | **0** |
| 字面宽/高中位数偏差 | ≤ ±1% 目标值 |

### 5.2 可变字体闸门

| 检查 | 阈值 |
|---|---|
| `fvar` 存在且 `wght` 轴 = 250–900 | 必须 |
| 7 个命名实例可实例化 | 全部 |
| 任意两 master 点结构一致率 | **100%** |
| 插值中间态（如 wght=450）无轮廓自交 | **0** |

### 5.3 特性闸门

| 检查 | 阈值 |
|---|---|
| GSUB feature tag 集合 ⊇ 思源原版 | 必须 |
| `locl` 存在且能切出日文字形（直/骨/次/令） | 必须 |
| `vert`/`vrt2` 竖排可用 | 必须 |
| `cmap` 码位数 ≥ 思源原版 | 必须 |
| 所有 lookup 引用的字形名均存在 | **0 悬空** |

### 5.4 视觉闸门

自动生成样张（HTML + 截图），至少覆盖：
- 常用 3000 字密排（12px / 16px，看灰度与脏点）
- 大字号单字（96px+，看轮廓质量）
- 中英混排（看基线与比例）
- 标点挤压、竖排、反白
- 与 PingFang SC / 思源黑 并排对照

## 5.5 铁律：数值测量不能代替看图

**任何一轮构建，必须实际渲染成图片并逐张看过，才能宣布通过。**

- 测量指标（bbox、负空间比、点数、绕向）只能证明"没坏"，不能证明"好看"。
- 旧版的教训：所有数值都在合理区间，但看图的第一眼就知道不对——端点碎、笔画糊、字挤。
- 视觉判断是最终裁决权，测量是辅助。两者冲突时，**以图为准**，然后回头解释数值为什么不敏感。

具体执行：
1. 每轮改动必须产出 PNG 截图（不是只看 HTML 源码）
2. 截图必须与参照字体（PingFang SC / 思源黑原版）**并排同尺寸**
3. 必须包含小字号正文（12–16px）与大字号单字（96px+）两种尺度
4. 发现问题先描述"看到了什么"，再去找对应的数值原因
5. 记录进 `docs/REVIEWS/YYYY-MM-DD.md`：截图路径 + 观察 + 结论

> 违反这条铁律的构建，一律视为未完成。

## 6. 环境与本机能力

| 项 | 实测值 |
|---|---|
| CPU | 6 核 aarch64（iSH / Alpine） |
| 内存 | 4096 MB（无 swap） |
| 磁盘可用 | 593 GB |
| Python | 3.12 + fontTools 4.55 + ufoLib2 + fontMath + numpy + PIL + brotli |
| 缺 | fontmake（需 pip）、harfbuzz CLI（需 apk add harfbuzz-utils） |
| 网络 | GitHub 资产 60–110 KB/s，`raw.githubusercontent.com` 不可用 |

**耗时估算**：单字形建模 ≈ 0.1–0.3 s；全量 4 万字形 × 7 master ≈ 8–24 小时。必须分批（按 Unicode 区段分片）并支持断点续跑。

**内存策略**：不要把全字库 load 进内存。一次处理一个区段（≤2000 字形），处理完写盘。

## 8. 风险登记

| 风险 | 概率 | 影响 | 应对 |
|---|---|---|---|
| CFF2 节点编辑 API 不成熟 | 中 | 高 | 先实例化静态再合并（见 4.1） |
| `locl` 在 SHS VF 中不可用 | 中 | 中 | 退路：出独立 JP 版 |
| 部件分割错误导致部件级变换错位 | 高 | 中 | 建立人工覆盖机制 + 抽样人工复核 |
| 全量处理时长超出预期 | 中 | 中 | 分片并行 + 断点续跑 |
| 视觉方向反复（审美疲劳） | **高** | 高 | **参数冻结机制**：P2 定稿后只改 bug，不改风格 |
| 曲线质量在极细/极粗端崩坏 | 中 | 高 | 250/900 单独做 QA，允许这两档用不同的 stroke_offset 曲线 |
