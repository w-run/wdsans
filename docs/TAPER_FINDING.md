# 笔末平切缺失 — 诊断报告（2026-11-19）

## 用户反馈
「笔末平切好像没有了？」

## 结论：确实缺失，且是继承自 SHS 的原始状态

### 量化证据（凸包法，4 字一致）
```
字体      端面凸包/面积比     判定
我们      1.029               内凹
SHS       1.029               内凹（同源）
OPPO      1.003               平切
HOS       1.001               平切
```

凸包比 1.00 = 完全凸（平切）；>1.02 = 内凹。
**我们与 SHS 完全相同，与 OPPO/HOS 有稳定差距。**

### 轮廓级根因
```
大  我们  捺轮廓 4段，签名 LCCC
    捺尖端 = C段: c1(551,235) c2(686,25) end(903,-77)
    -> 三次曲线收尾，末端弯曲

大  OPPO  捺轮廓 15段，签名 QMLLLLLLLLLQQMLQMQM
    捺尖端 = L段: end(910,-101)
    -> 直线段收尾，末端是一个角（平切）
```

4 个测试字（大/人/天/夫）全部同构：
- 我们：捺尖是 C 段，轮廓独立拆分成多个 4 段小轮廓
- OPPO：捺尖是 L 段，整字合并成单一大轮廓

### 为什么之前没发现

- 六项笔画风格指标里「笔末切角」测的是**横笔端面倾斜量 dx**，
  全部为 0.0（我们/SHS/OPPO/HOS 都是 0），那个指标正常。
- 撇捺末端形态从未被量化过。
- 本轮测量前 4 次方法都失败（扫错边/噪声主导），
  最后用「端面凸包面积比」才得到稳定结果。

### 测量方法踩坑记录（4 次失败）
```
1. 沿主轴采样法: 主轴估算错误（闭合轮廓首末点重合）
2. 位图右下象限剖面: 混入了侧边，不是端面
3. 每行最右点拟合: 对角笔画的「最右点」追踪的是侧边
4. PCA 端面拟合: 端面只有几个像素宽，rms 被噪声主导
✅ 5. 端面凸包面积比: 稳定，4 字结果一致，与目视吻合
```

### 修复方向（下一轮）

把撇/捺末端的 C 段改成 L 段（曲线收尾改直线切角）。

🔴 硬约束：三档 VF 要求段数+操作符完全一致。
   C→L 会改变段类型签名，必须三档同步且验证不触发
   VarLibCFFPointTypeMergeError。

🔴 历史教训：m_termface（C→L 端面拉直）曾因判据过宽
   把大量真实弧线也拉直（曲线 42.3%→32.7%），已彻底废弃。
   本次只能针对「撇/捺最末端一段」，判据必须严格。

参考实现：OPPO 的捺尖是 L 段，端点是角点。
可以取末段 C 的终点 + 前一个控制点方向，生成等效的 L 段。
