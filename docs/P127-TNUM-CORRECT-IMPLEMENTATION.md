# P127 · tnum 正确实现：复用自己的默认数字 + 平移居中

日期：2026-11-07
状态：已实现并验证（4 档字重粗细比值全部 1.00）

## 问题演进

### 第一版（错误）：直接搬 Mona 的 .tf 字形

```
           默认      tnum
Thin      14980    26795   ← 粗 79%
Regular   24809    26795
Heavy     46079    26795   ← 细 42%
```

tnum 在全部字重下墨量完全相同 —— 不随字重变化。

原因：为了绕开「旧 gvar delta 与新点数不匹配」的反序列化断言，
我把槽位的 gvar 清空了。

### 第二版（部分修复）：三档采样合成 delta

变化幅度从 0 提升到 1.80x，但默认数字是 3.08x，仍不协调。

原因：Mona 的 .tf 字形使用 wdth 轴 + 多段 tuple，
而我们字体只有 wght 轴，无法完整复现插值曲线。

### 第三版（正确）：复用自己的默认数字

关键洞察 —— **不必用 Mona 的 .tf 字形**。
把「自己的默认数字」水平平移到等宽格子内即可：

```python
shift = (A400 - orig_adv) // 2      # 居中偏移
新轮廓 = 默认数字的坐标 + shift     # 点数完全一致
gvar   = 直接复用默认数字的 tuple    # 只有 wght 轴，完全匹配
pp2.x  = 目标字重宽度 - A400        # 补上宽度变化
```

因为点数天然相同，gvar delta 可以完整复用，
不存在轴不匹配和点数不符的问题。

## 教训

**移植字形时，优先「复用自己的字形 + 最小变换」，而不是「搬运外部字形」。**

- 搬外部字形 → 点数不同、轴不同、单位不同，每一样都要单独处理，
  且容易引入无法追查的偏差
- 用自己的字形 → gvar 天然匹配，只需处理「位置」和「宽度」两个可控量

对 tnum 这种「只是改变格子宽度」的特性，
字形本身完全不需要替换，只需平移。
