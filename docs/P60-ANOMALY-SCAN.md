# P60：全库异常扫描 —— 发现一个度量陷阱

## 动机

本项目经历大量修改（减细、去脚、拉丁合并、Ext-A 补齐、复合内联）。
这些操作可能让**部分字形偏离设计**，而抽查（我此前只查了十几个字）覆盖不到 65,535 个。

本轮做**全库内部检视**：不依赖参照，找「看起来不对劲」的字形。

## 扫描方法

对每个字形算三个指标，标出离群者：

| 指标 | 阈值 | 意图 |
|---|---|---|
| bbox 越界 | x>1200 或 y>1200 或 x<−300 或 y<−400 | 找到跑出字面框的 |
| 空心 | area/bbox < 2% | 疑似减细过度 |
| 实心 | area/bbox > 92% | 疑似部件粘连 |

## 第一轮结果：三类离群

```
扫描 65535 个有轮廓字形
超框: 8 个    空心: 2 个    实心: 32 个
```

### 实心 32 个：全是误报

```
U+2501 ━  U+2503 ┃  U+2578 ╸  U+2579 ╹
U+2580 ▀  U+2581 ▁  ...  U+259F ▟
```

**全部是制表符/方块元素（U+2500-259F）**，按设计就是**纯色实心块**。
填充率 1.0 是它们应有的样子。

### 超框 8 个：正常工作

| 码位 | 字符 | 说明 |
|---|---|---|
| U+20DD | ⃝ 组合圆圈 | 组合标记，需覆盖在前一字符上，故范围在负坐标 |
| U+20DE | ⃞ 组合方框 | 同上 |
| U+2E3A | ⸺ 二倍长横 | 破折号类，本来就超宽（x 到 1623）|
| U+2E3B | ⸻ 三倍长横 | 更宽（x 到 2405）|
| U+302A | ゚ 声调符 | 缩小符号，在负坐标区 |
| U+302B | ゛ 声调符 | 同上 |
| U+3031 | 〱 竖排假名重复 | 竖排专用，纵向到 1316 |
| U+3032 | 〲 同上 | 同上 |

**全部是按设计就该超出普通字面框的符号。**

### 空心 2 个：需要核查

```
U+3AB3「㪳」  area=1877   bbox=876x862   填充率 0.0025
U+81E6「臦」  area=10789  bbox=900x827   填充率 0.0145
```

## 第二轮：与 Noto 逐字对比

| 码位 | 我们面积 | Noto 面积 | 判定 |
|---|---|---|---|
| U+3AB3 | **1877** | 14857 | **差 8 倍！** |
| U+81E6 | 10789 | 5405 | 差 2 倍 |

**U+3AB3 少了 87% 的面积**，看起来像严重缺陷。

## 第三轮：看渲染图

渲染 200px 的 `㪳` 和 `臦`，与 Noto 并排：

图：`docs/img/p60-anomaly.png`

**肉眼结论：两个字都渲染正常，笔画完整，与 Noto 看不出差别。**

## 第四轮：找到根因 —— 度量方法有缺陷

两个字的**点数和轮廓数完全一致**：

```
U+3AB3  我们: 轮廓=6  点=68(on 24/off 44)  面积=1877
U+3AB3  Noto: 轮廓=6  点=68(on 24/off 44)  面积=14857
```

点一样、轮廓一样、视觉一样，面积却差 8 倍 —— **只能是面积算法的问题**。

`AreaPen` 算的是**有向面积的代数和**。

对「外轮廓 + 内轮廓（孔）」的正确字形：
```
外轮廓 顺时针 → +A
内轮廓 逆时针 → −a
总和 = A − a   ✓ 正确（挖掉孔）
```

若某个字形的内轮廓**与外轮廓同向**：
```
外轮廓 → +A
内轮廓 → +a     ← 同向，相加而非相减
总和 = A + a   ← 偏离真实墨量
```

**不同字体对轮廓绕向的处理不同**，同一个字在 Noto 是「相减」、
在我们这里变成「相加」，结果自然天差地别。

而且我当时用了 `abs(area)`，**掩盖了负值/异常**，让问题更隐蔽。

## 第五轮：用渲染像素重测（绕开绕向问题）

直接渲染 800px，累积灰度当墨量——**不涉及任何绕向计算**：

| 码位 | 我们 | Noto | 比值 |
|---|---|---|---|
| U+3AB3 㪳 | 128595 | 146812 | **0.876** |
| U+81E6 臦 | 204632 | 235276 | **0.870** |
| U+56FD 国 | 197480 | 230349 | 0.857 |
| U+6C38 永 | 121641 | 155240 | 0.784 |

**U+3AB3 的墨量是 Noto 的 0.876，与「国」0.857、「永」0.784 同区间。**

即：它**正常经历了减细**，没有任何异常。

## 结论

| 项 | 结果 |
|---|---|
| 超框 8 个 | 全为组合标记/长破折号/竖排符号，正常 |
| 实心 32 个 | 全为制表符方块，正常 |
| 空心 2 个 | **视觉正常**，面积差是度量缺陷导致 |
| 全库真实异常 | **0 个** |

## 教训（重要）

**面积不是可靠的字形健康指标。**

`AreaPen` 依赖轮廓绕向：
- 同向轮廓 → 面积相加（错）
- 反向轮廓 → 面积相减（对）

不同字体、不同工具导出的绕向不一致，跨字体比较面积会得到荒谬结论。

**正确的墨量度量：**
1. **渲染像素**（最可靠，所见即所得）——本轮最终采用
2. 轮廓面积绝对值之和（|每个轮廓|相加，不看符号）

**绝不能直接用 `abs(AreaPen 总和)` 跨字体比较。**

## 特别记录

我在 P55（几何健壮性扫描）里也用 `AreaPen`，但那里只判断「是否 == 0」和「是否 < 200」，
对同向/反向不敏感（零面积永远是零，极小碎片也永远是极小），**那个结论仍然有效**。

但一旦跨字体**比较面积大小**，就会踩这个坑。
