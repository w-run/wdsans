## 1. 「折角微圆」被证伪，此项取消

我在前几轮一直把「OPPO 折角微圆 8–14u」列为待办，**这是错的**。

### 证据一：角点角度统计

对 口日田目回且旦旧早 九个字，统计所有 on-curve 角点角度：

| 字体 | 角点数 | 角度分布 |
|---|---|---|
| Noto | 164 | **{90: 164}** |
| 本产物 | 164 | **{90: 164}** |
| OPPO | 148 | **{90: 148}** |
| HOS | 172 | **{90: 172}** |

**648 个角点，全部 90°，一个例外都没有。**

### 证据二：800px 渲染 + 5x 像素放大

把「口」左上角放大到像素级，三个字体都是**硬直角**，没有任何圆弧过渡。

### 我为什么会看错

低分辨率缩略图上的**抗锯齿**会在直角处产生 1–2px 的灰度过渡，
肉眼看起来像圆角。这是典型的「看图看出不存在的特征」。

**教训**：视觉判断必须在足够高的分辨率下做，
并且要用可量化的量（这里：角点角度）交叉验证。

## 2. 去脚判据 v3 → v5：修掉多横字形的误伤

### 症状

v3 处理后，「冒」「昌」「晶」**内部糊成黑块**：

```
昌 v3 错误:
  c0(上"日"内横) 被下移 63 → 撞上外壳底边
  c5(下"日"底横) 被下移 48 → 正确
```

### 三次错误定位

| 假设 | 实测结果 |
|---|---|
| 选错了 bar（该选最低那条） | 加条件后仍错，说明不是选择问题 |
| 下移后与相邻横画重叠 | 「口」「日」也报重叠，但它们是**对的**（重叠对象是外壳本身）|
| **外壳形状不同** | ✅ 找到根因 |

### 真正的根因

```
口  c0: 8 点，底边是两段短线（81、78），宽 750 → ⊓ 形，底部开口 → 有脚
日  c0: 8 点，底边 80、78，宽 656              → ⊓ 形，底部开口 → 有脚
昌 上"日" c2: 4 点，底边横跨全宽 606          → 闭合矩形 → 无脚，跳过
```

**只有外壳底部开口（⊓ 形）时，才存在「脚」。**
闭合矩形没有脚——它的底横已经就在底部了，再下移只会撞上底边。

### v5 判据（最终）

```python
def _has_full_bottom_edge(seg, tol=3.0, span_ratio=0.5):
    """底部 30% 区域内，是否有横跨超一半宽度的水平边。"""
    # 有 → 已闭合 → 无脚
```

叠加到原有条件上：宽扁条 + 被高外壳包含 + 在下半部 + 底部开口 + 间距 [18,140]。

## 4. 本轮的方法论收获

**「缩略图看不出来」出现过两次，都是真实事故：**

1. 去脚误伤谚文/假名/拉丁：缩略图无异常，像素差分显示位移达 97px
2. 折角微圆：缩略图上「看出」圆角，量化后 648 个角点全是 90°

两次方向相反（一次漏看真问题，一次看出假问题），但根因相同：
**低分辨率目视不能作为判据，必须配合量化。**
