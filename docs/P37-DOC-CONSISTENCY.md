# P37：文档一致性核查 —— 发现两处统计口径混淆

## 背景

母版改动（cmap 44810→44905）后，需核查散落在 43 份文档里的数字是否同步。

## 发现一：PARAMS.md 七档值有三个错（真实缺陷）

PARAMS §3.3 的「字顶/字底」列，此前只修过 Regular/Medium/Bold/Heavy，
**Thin/Light/Normal 仍是未验证的旧值**。用 BoundsPen 全部重测「国」：

| 档位 | 原文档 | 实测 |
|---|---|---|
| Thin | 810 / -92 | **778 / -68** |
| Light | 815 / -94 | **780 / -69** |
| Normal | 820 / -96 | **786 / -72** |
| Regular | 789 / -74 | 789 / -74 ✓ |
| Medium | 795 / -77 | **796 / -78** |
| Bold | 804 / -82 | **804 / -83** |
| Heavy | 813 / -88 | 813 / -88 ✓ |

已全部更新，并在表头标注口径为「「国」单字」。

## 发现二：我误判了 P27b，差点改错（我的错误）

看到 P27b 写「汉字顶 832」而 PARAMS 写 789，我判断「832 是错的」，
做了一次全局 `832 → 789` 替换。

**这是错的。** 回看 diff 才意识到：

| 文档 | 数值 | 口径 |
|---|---|---|
| P27b「汉字顶（81 字中位）」| **832** | 58 个字的**中位数** |
| PARAMS「字顶/字底」| **789** | 「国」**单字** |

实测复核（58 字样本）：

| 字体 | 字顶中位 | 字底中位 |
|---|---|---|
| 我们 400 | **832** | −73 |
| Noto 400 | 838 | −79 |
| OPPO 400 | 825 | −100 |
| 鸿蒙 400 | 836 | −71 |

**832 完全正确，是 58 字中位（含比「国」更高的字，如「直」「骨」）。**
789 是「国」的单字值。两者都对，只是口径不同。

已回滚那次误改，并给两个文档都加上口径说明，防止下次再混。

## 教训

**「两个文档数字不一致」不一定是错，可能只是统计口径不同。**

我在替换前应该先确认「832 是怎么算出来的」，而不是看到 789≠832 就假定 832 错。
这是个危险动作：全局替换把一个正确的数据破坏了。

幸好 diff 检查发现了。**这也说明「改完必须看 diff」是必要的护栏。**

## 修正后的口径对照（写进两份文档）

| 指标 | 口径 | 用途 |
|---|---|---|
| 832 / −73 | 58 字中位 | 判断整体字面饱满度、与参照字体对比 |
| 789 / −74 | 「国」单字（400 档）| 逐档校准、PARAMS 参数表 |

两者不矛盾：中位数含更多字形，值天然更高。
