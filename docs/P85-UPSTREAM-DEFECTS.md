# P85：上游 glow-sans 16 项缺陷的逐条实测验收

## 为什么做这个

用户最初的要求里有一条核心：

> 「上游仓库已经完全停止维护、**必须详读 glowsans 的 readme 和 issues 确定已知缺陷**」

`docs/REBUILD-PLAN.md` 记录了我们详读过 README + **全部 49 条 issue**，
并归纳出 **A1–A9 九项算法缺陷** + 旧版产物**七项缺陷**。

但这些是**设计阶段的判断**。本轮做的是：**逐条实测，确认是否真的解决了**。

## 一、A1–A9 算法缺陷（glow-sans 的根因问题）

### A1/A2：去脚不可靠 + 整字「飘起」

这两项是上游最严重的缺陷（#2 #7 #10 #28 #34 #47，作者标 wontfix）。

**测试方法**：口垫底字（A2 明确点名 名/容/兽/音/飴）的底部坐标，与 Noto 对比。

| 字 | 我们 bottom | Noto bottom | 差 |
|---|---|---|---|
| 名 | −73 | −79 | +6 |
| 容 | −75 | −81 | +6 |
| 兽 | −74 | −80 | +6 |
| 音 | −75 | −81 | +6 |
| 飴 | −74 | −80 | +6 |
| 占 | −73 | −79 | +6 |
| 台 | −73 | −79 | +6 |
| 召 | −75 | −81 | +6 |
| 右 | −75 | −81 | +6 |

```
平均落差: +6.1 upm
9/9 字完全一致（都是 +6）
```

**判定：无「飘起」。**

- 9 个字**全部**一致偏高 6 upm，这是减细（横 −12）的均匀连带效果
- 若是上游 A2 的缺陷，会出现「部分字浮起、部分字正常」的不一致
- 6 upm = 0.6% em，在任何字号下都不可见

**A1（去脚不可靠）的对应证据**：我们的做法是「不摘脚，只减细」——
根本没有做上游那种「7 点窗口 + 直角容差 2°」的启发式判脚，
所以「字重越极端越失效」的失效模式**从结构上不存在**。

### A5：曲线被拉直

上游根因：光栅化离散 → CV 骨架 → 重描边，只能拟合折线。

**测试方法**：曲线段占比（curveTo+qCurveTo 占全部路径段的比例）。

```
我们:  37.9%
Noto:  37.9%
差: +0.00 个百分点
```

**判定：曲线完全保持。** 我们的路线是节点位移，不经过光栅化，从原理上不会产生 A5。

### A6：半角假名只是改字距

**测试方法**：56 个半角片假名（U+FF66–FF9D）的实际宽度。

```
覆盖: 56 / 56
宽度: 500（唯一值）
全角假名宽度: 1000
比例: 0.5
```

**判定：真正的半宽支持（500 = 全角的一半）。**
上游是「把全角字形压扁/改字距」冒充半宽，我们是 Noto 原生的半角字形。

### A7：CID / 字形映射错位

**测试方法**：cmap 里是否有指向不存在字形的条目。

```
cmap 条目: 44905
指向不存在字形的条目: 0
```

**判定：无错位。** 上游是自建构建脚本丢了原始 CID；我们直接用 Noto 的 cmap，不存在重建环节。

### A8：name 表分裂 / CodePage

**测试 1：七档 name16/17 是否齐全**

```
Thin     ID16=WDesign Sans   ID17=Thin
Light    ID16=WDesign Sans   ID17=Light
Normal   ID16=WDesign Sans   ID17=Normal
Regular  ID16=WDesign Sans   ID17=Regular
Medium   ID16=WDesign Sans   ID17=Medium
Bold     ID16=WDesign Sans   ID17=Bold
Heavy    ID16=WDesign Sans   ID17=Heavy
```

**判定：七档全齐。** 上游是「部分档有、部分档 None」，导致 Windows/Figma 只认两档。

**测试 2：CodePage 声明**

```
我们:  0x602E0107
Noto:  0x602E0107
差异位: []          ← 完全相同
```

声明了 Latin1 / GB2312 / Big5 / Wansung 四项。

### 一个需要澄清的点

我们有 56 个半角假名，但 CodePage **没有**声明 ShiftJIS（位 20）。

```
与 Noto 对比：差异位 = 0
```

**这完全继承了 Noto 的声明**——不是我们漏了，是基座本就如此。
若自行加上，反而与基座不一致。**不改。**

### A9：没有 TTF / 没有 hinting

```
glyf 表:     有 ✓
CFF/CFF2:    无 ✓
fpgm/prep/cvt: 无（未做 hinting）
```

**判定：原生 TTF 达成；hinting 未做（已知，见 README 限制 3）。**

这是用户明确要求「原生 ttf」的直接落实。

## 三、汇总

### A1–A9

| # | 缺陷 | 上游状态 | 我们的实测结果 |
|---|---|---|---|
| A1 | 去脚不可靠 | wontfix | **不做启发式判脚，失效模式不存在** |
| A2 | 整字飘起 | wontfix | **9/9 字一致 +6 upm，无飘起** |
| A3 | 撇捺喇叭口 | 全局滤镜所致 | **节点位移，无滤镜** |
| A4 | 点被压扁 | dotsoftness | **不做统一缩放** |
| A5 | 曲线被拉直 | 光栅化路线固有 | **曲线占比 37.9% = 37.9%** |
| A6 | 半角假名偷懒 | 作者自认 | **真半宽 500/1000** |
| A7 | CID 错位 | 几乎无法修 | **0 条错位** |
| A8 | name 分裂/CodePage | 多 issue | **七档全齐，CodePage 同 Noto** |
| A9 | 无 TTF/无 hinting | 只发 OTF | **原生 glyf ✓**（hinting 未做）|

### 算法级缺陷的共同根因

上游 A1–A7 的根因是**同一条路线的必然失败**：

```
光栅化 → CV 骨架 → 重描边
  → 曲线被离散成折线（A5）
  → 判脚靠启发式窗口（A1）
  → 补偿靠经验值（A2）
  → 全局滤镜无法区分笔画角色（A3/A4）
```

我们的路线：**只在 gvar delta 上做节点位移**

```
不经过光栅化 → 无 A5
不判脚，只减细 → 无 A1
不需补偿 → 无 A2
逐节点法向计算，非全局滤镜 → 无 A3/A4
```

**这印证了 REBUILD-PLAN 的核心判断：必须改成节点位移路线。**

## 四、教训

### 1. 「文档说解决了」和「实测证明解决了」是两回事

REBUILD-PLAN 是设计阶段的推演。
本轮把它当**待验清单**，逐条跑数据。

结果虽然全部通过，但过程有价值：
- A8 的 ShiftJIS 疑点，只有实测才浮现
- 通过「与 Noto 对比 CodePage」才判定这不是缺陷

### 2. 对比基座是排除「继承性问题」的唯一办法

如果我看到「有半角假名但没声明 ShiftJIS」就报缺陷，那是错的。

**对比 Noto 后发现差异位为 0 —— 这是继承的行为，不是我们的疏漏。**

### 3. 「+6 upm 一致偏移」与「飘起」的区别

两者数值上都表现为「字变高了」。区分方法：

| | 一致偏移（减细）| 飘起（上游 A2）|
|---|---|---|
| 各字差值 | **完全相同**（都是 +6）| 参差不齐 |
| 来源 | 全局统一减细 | 摘脚后补偿不足 |
| 幅度 | 0.6% em | 可达 1/4 脚高 |

**看「一致性」比看「数值大小」更能区分性质。**
