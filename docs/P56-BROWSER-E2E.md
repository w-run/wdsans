# P56：浏览器端到端验证（Chrome + @font-face）

## 为什么做这个

此前所有验证都走这两个工具：
- `hb-shape` / `hb-view`（HarfBuzz）
- `fontTools`（直接读表）

但**字体最终是在浏览器里用的**。Chrome 的加载路径与 HarfBuzz 不同：
1. 下载 WOFF2 → **OTS 清洗** → 交给排版引擎
2. 按 CSS `@font-face` 的 `font-weight` 范围匹配
3. 失败时**静默回退**到下一个字体（不报错，用户只看到不对的字形）

所以必须用真浏览器验一遍。w-box 上有 `google-chrome`。

## 一、加载成功性（document.fonts API）

```css
@font-face { font-family:"WDS";   src:url("...Regular.woff2") format("woff2"); font-weight:400; }
@font-face { font-family:"WDS";   src:url("...Bold.woff2")    format("woff2"); font-weight:700; }
@font-face { font-family:"WDSVF"; src:url("...VF.woff2")      format("woff2"); font-weight:250 900; }
@font-face { font-family:"SUBSET";src:url("...sub6763.woff2") format("woff2"); }
```

结果：

| 字体面 | status |
|---|---|
| WDS w=400 | **loaded** |
| WDS w=700 | **loaded** |
| WDSVF w=250-900 | **loaded** |
| SUBSET w=normal | **loaded** |

**4/4 全部 loaded**，没有回退，没有 OTS 拒绝。

## 二、字体是否真的被应用（宽度比对）

`loaded=true` 只说明文件下载并解析成功，
还需证明**排版时确实用了它**。方法：比较自定义字体的测量宽度与回退字体。

### 第一次尝试：用中文测 → 失败

```
WDS 400   width=168.0  fallback=168.0  [与回退相同!]
```

看起来像没生效，但**这是中文字体的正常现象**：
汉字全角等宽，1000/1000 upm，任何字体宽度都相同（见 P45）。

**用中文测不出字体是否被应用。**

### 第二次尝试：用拉丁字符（HAMBURGefi）→ 成功

| 字体面 | 自定义宽度 | 回退宽度 | 判定 |
|---|---|---|---|
| WDS 400 | **236.20** | 247.20 | ✓ 生效 |
| WDS 700 | **243.32** | 247.20 | ✓ 生效 |
| VF 425 | **236.95** | 247.20 | ✓ 生效 |
| VF 600 | **241.37** | 247.20 | ✓ 生效 |
| VF 900 | 247.40 | 247.20 | （见下，误报）|
| SUBSET 6763 | **236.20** | 247.20 | ✓ 生效 |

**全部与回退字体不同，确认自定义字体真正参与了排版。**

## 三、VF 字重插值（浏览器视角）

| wght | 测量宽度 |
|---|---|
| 250 | 231.80 |
| 400 | 236.20 |
| 500 | 239.32 |
| 700 | 243.34 |
| 900 | 247.40 |

**单调递增，间距渐大**（细体变化慢、粗体变化快），
与 P53 发现的固定偏移规律方向一致。

浏览器端的 VF 插值工作正常。

## 四、子集与全库一致性（浏览器验证）

```
WDS 400（全库）   236.20
SUBSET 6763       236.20   ← 完全相同
```

**子集化没有改变任何度量。**这是 P42 结论在浏览器中的独立确认。

## 五、一个测量陷阱：阈值误报

VF 900 那行显示「未生效」，但：

```
自定义: 247.40
回退:   247.20
差值:     0.20   ← 小于我的判定阈值 0.5
```

**这是巧合**：VF 900 的拉丁宽度恰好接近回退字体 monospace。

证据：VF 900 的宽度 247.40 与 VF 700 的 243.34 明显不同，
且整条 250→900 曲线单调，说明插值本身正常。

**问题在于我的判定方法，不在字体。**

正确的判定应该是：
- 不靠单点宽度，而看**整个字重序列是否单调变化**
- 或直接用 `document.fonts.check()` 的返回值

## 六、结论

| 项 | 结果 |
|---|---|
| Chrome 加载 4 个字体面 | **4/4 loaded** |
| 自定义字体是否生效 | **是**（拉丁宽度与回退明显不同）|
| VF 插值 | 250→900 宽度单调 231.80→247.40 |
| 子集与全库 | 宽度完全相同（236.20）|
| 视觉渲染 | 三种字重 + VF 425/600 均正常显示 |

**全部 29 个交付物在真实浏览器环境中可加载、可排版。**

## 七、教训

**同一个「相同」，可能是正常，也可能是缺陷，取决于测的是什么。**

第一次测中文发现宽度相同，差点误判「字体没生效」——
实际是中文字体等宽特性（P45 的结论）。

第二次测拉丁又遇到 VF 900 宽度接近回退，差点误判「该字重失效」——
实际是阈值设置不当造成的误报。

**两次「相同」都是假警报。**
判定「字体是否生效」不能靠单点数值比对，
要靠「序列是否随参数单调变化」这种结构性证据。
