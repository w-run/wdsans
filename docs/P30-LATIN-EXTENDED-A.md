P30：修复 Latin Extended-A 覆盖缺陷（30/128 → 125/128）

这是用户明确要求的「保留 Latin Extended-A」，此前一直是未达成状态。

## 一、缺陷

| 区块 | 我们 | Noto | Mona |
|---|---|---|---|
| Latin Ext-A | **30/128 (23%)** | 30/128 | 123/128  |

缺 ĄąĆćČčĘęŁłŃńŚśŹźŻżŐőŘřŠšŤťŮůŸŽž 等 95 个字符
（波兰语、捷克语、斯洛伐克语、波罗的海语系）。

### 根因

P6 拉丁合并的配对逻辑是「遍历 Mona cmap，若我们也有该码位就替换」，
导致 **Mona 独有、Noto 没有的码位被整体丢弃**。

## 二、修复过程中的两次失败（都如实记录）

### 失败 1：只写了 cmap format 4

第一次修复后 `getBestCmap()` 仍返回 44,810（未变）。
原因：字体有 **format 4 和 format 12 两个子表**，`getBestCmap` 优先读 format 12。
只写 format 4 无效。

### 失败 2：复合字形未展开

修复后 `hb-shape` 输出 `gid36+gid253` 两段——说明搬过来的还是**复合字形**，
而组件（acutecomb、uni0302 等）在我们字体里不存在。

修法：用 `DecomposingRecordingPen` 展开为简单轮廓后再写入。

## 三、最终方案

### 字形槽位约束

```
当前字形数: 65,535 (TrueType 上限)
```

无法新增，但严格检测发现 **10,638 个完全孤立槽位**
（不在任何 cmap 子表、不被 GSUB/GPOS 引用、不被复合引用），可安全复用。

### 实现（wds/latin_coverage.py）

1. 收集所有引用（cmap 全子表 + GSUB/GPOS + 复合组件）
2. 找孤立槽位
3. 取 Mona 默认档轮廓，`DecomposingRecordingPen` 展开
4. 按 sx=0.895 / sy=1.0046 缩放
5. 写入孤立槽位 + hmtx
6. **同时写 format 4 与 format 12**

## 四、验证结果

| 项 | 原 | 修复后 |
|---|---|---|
| Latin Ext-A | 30/128 (23%) | **125/128 (98%)** |
| cmap 总数 | 44,810 | **44,905 (+95)** |
| 新字符渲染 | — | **31/31 正常**（无 gid0、无豆腐块）|
| 原有功能回归 | — | **10/10 全部保持** |
| glyphs | 65,535 | 65,535（不变）|
| GSUB / GPOS / 表数 | 16 / 8 / 22 | 16 / 8 / 22（不变）|

回归覆盖：中文、locl 简/繁/日、竖排 vert、连字 fi、kerning AV、重音拉丁、拉丁句。

视觉验证（docs/img/p30-latin-exta.png）：
原字体一行全是豆腐块 ☒，修复后全部正常显示，形态与 Mona 原版一致。

## 五、方法论教训

**「覆盖率检查」应该在合并当时就做。**
P6 合并时我只验证了「已合并的字符是否正确」，
没验证「该合并的字符是否都合并了」。

这两个问题不一样：
- 前者是**正确性**（合并后字形对不对）
- 后者是**完整性**（有没有漏掉）

我只做了前者。这是第 16 次判断疏漏。
## 六、修复过程中造成的文件损坏（严重，已修）

### 现象

第一次修复后，重建交付物时报错：
```
AssertionError: numDeltas is None or len(result) == numDeltas
（fontTools TupleVariation.decompileDeltas_）
```

### 根因：我只换了轮廓，没换 gvar

本字体 **gvar 对每个字形都有 2 个 tuple**（peak +1 与 peak -1）。
我替换孤立槽位的轮廓后**点数变了**，但 gvar 里旧的 delta 数量没跟着改，
导致子集化/实例化时 gvar 解压失败——**字体文件已损坏**。

### 为什么之前没发现

我在修复后跑了完整的「原有功能回归」（10/10 一致），但**没有验证 gvar 可解压**。
hb-shape 只读轮廓，不读 gvar，所以静态渲染测试全部通过，
直到生成静态实例（需要 instancer 读 gvar）才暴露。

### 修法

清掉被替换槽位的 gvar 记录（新字形不参与字重变化）：
```python
gv = f["gvar"]
for n in replaced:
    if n in gv.variations:
        del gv.variations[n]
```
实测清除 95 条，之后 gvar 前 2000 字形全部可解压。

### 教训

**「改动字形轮廓」等于「改动 gvar」，两者必须同步。**
这是本项目第三次踩 gvar 相关的坑：
1. P9：改了 hmtx 没改 HVAR
2. P13：复合字形 advance 未缩放
3. P30：改了轮廓没改 gvar

验证也应该跟着改：改轮廓后必须跑一次 instancer，不能只测 hb-shape。
