## 2. 修掉的 4 个级联 bug（每个都是实测定位，不是猜）

### bug 1：`endPtsOfContours` 语义读错（最关键）

```python
# 错（我最初写的）
ends = list(g.endPtsOfContours) + [len(coords)]
# 「一」的 endPts=[3] → 切成 [coords[0:3], coords[3:4]]
# 变成「3 点轮廓 + 1 点轮廓」，真实 4 点矩形被拆碎 → 横厚改不动

# 对
segs = []
start = 0
for end in g.endPtsOfContours:
    segs.append(coords[start:end + 1])   # endPts 是「结束索引」，含
    start = end + 1
```

`endPtsOfContours=[3]` 的含义是「1 个轮廓，第 0..3 点」，不是「3 个点」。

### bug 2：角点位移取平均而非矢量和

横边给的位移被相邻竖边平均掉 → 净高不变（实测 82.0 → 82.0）。
改为标准斜接（miter）：角点位移 = 入边位移 + 出边位移。

### bug 3：`disp[i]` 和 `disp[j]` 双重累加

`j = (i+1) % n`，同一条边被两端各收一次且方向相反 → 互相抵消，
实测「一」只有 2 个角点动、2 个不动。改为「逐顶点看前后两条边」。

### bug 4：点级法向在角点处由对角线决定

4 点矩形的每个点都是角点，用相邻两点连线算法向等于算对角线 → 横竖判据混乱。
改为**判边不判点**：边接近水平 → 法向竖直 → 改横厚；反之改竖宽。

## 3. 方法：逐轮廓自校准

```python
for seg in contours:
    a0 = abs(area(seg))
    best = min over sign in (+1,-1) of abs(area(offset_miter(seg, d_h, d_v, sign)))
    out.append(best if best < a0 else seg)
```

**为什么必须自校准**：实测「国」需要 +5 才减墨，其余字需要 -5。
Noto 的轮廓绕向**不统一**，任何全局符号都会解错一半字形。
这跟 glow-sans 用固定阈值（detect-feet.js 的 2° 直角容差）是同一类错误，
差别在于我们用「面积必减」这个**几何不变量**做判据，而不是固定角度。

## 4. 认知纠错（本轮新增，前文已列 3 条，这里补 2 条）

### 纠错 4：等比缩放不改变墨密度

字面 ×0.985 → 密度 0.440 仍是 0.440，只有宽 848→835 变了。
数学必然：面积与 bbox 同比缩放。**「收字面」和「更透气」是两件事。**

### 纠错 5：「出脚」不是「低于基线」

四个字体都下探到基线以下，OPPO 在「甲/申/明」上反而更深（-108/-111/-127）。
「口」底部在 Noto 里是齐平方块（y -51~-55）。
**出脚 = 部件竖起处顶端的小方突**，判据待下一轮重新定义。
