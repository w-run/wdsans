# P83：SVG 锚点验证（视觉 + 标尺 + 数据三方对照）

## 按目标要求做的方法

目标明确要求：「笔画验证可以不仅靠数据计算，还可以转换 svg 看锚点
并用你的视觉看整体，细节用标尺」。

本轮完整走了一遍：

```
tools/glyph_svg.py → SVG（带锚点编号 + 100 单位网格 + 基线/cap/字面框标尺）
        ↓
rsvg-convert → PNG
        ↓
视觉对比 + 点数统计
```

## 一、视觉观察（「永」字）

| | 我们 | OPPO |
|---|---|---|
| 轮廓数 | **7** | **3** |
| 点数 | **78** | **64** |

### 看到的现象

1. **我们的每一笔都是独立轮廓**——点、横、竖、撇、捺各自闭合
2. **OPPO 把相邻笔画连在一起**——3 个轮廓就是几组连笔
3. 我们底部有一段**密集点簇**（编号 0/1/71/70/69、42-46）

### 我当时的推测（后来被推翻）

> 「点数多 22%，是减细造成的——减细在各笔画端点制造了额外控制点」

## 二、数据验证（推翻推测）

扩到 10 个字统计：

| 字体 | 轮廓数 | 点数 | 每轮廓点密度 |
|---|---|---|---|
| **我们 Regular** | **52** | **515** | 9.9 |
| **Noto 400** | **52** | **515** | 9.9 |
| OPPO 400 | 28 | 516 | 18.4 |
| 鸿蒙 400 | 28 | 431 | 15.4 |

```
我们 vs Noto:
  轮廓数: 52 vs 52  (+0.0%)
  点数:   515 vs 515  (+0.0%)
```

### 结论完全反转

**我们的轮廓数和点数与 Noto 逐字相同。**

- 减细**没有**增加任何控制点
- 底部的密集点簇是 **Noto 原生**的，不是我们造成的
- 「点数多 22%」是我把**单字**（永）的数据当成普遍规律的误读

## 三、真正的发现：OPPO 走了另一条路

| 字体 | 轮廓数（10字）| 每轮廓点数 |
|---|---|---|
| 我们 / Noto | **52** | 9.9 |
| OPPO / 鸿蒙 | **28** | 15.4–18.4 |

```
OPPO 轮廓数只有我们的一半，但总点数几乎相同（516 vs 515）。
→ 说明 OPPO 把多个笔画**合并进同一个轮廓**（连笔），
   用更多点描述一条更长的连续路径。
```

### 这是设计哲学差异，不是优劣

| 路线 | 代表 | 特点 |
|---|---|---|
| **笔画分离** | Noto / 我们 | 每笔独立闭合轮廓，改一笔不影响其他笔 |
| **连笔合并** | OPPO / 鸿蒙 | 相邻笔画并入同一轮廓，路径更连续 |

**我们的路线是 Noto 的路线**——这是基座决定的，也是铁律要求的
（「只移动节点，不增删节点」→ 拓扑结构必须与 Noto 一致）。

## 四、铁律得到验证

AGENTS.md 第一条铁律：**只移动节点，不增删节点**。

本轮给出了直接证据：

```
10 个汉字，我们与 Noto 的轮廓数、点数全部相同：
  轮廓 52 = 52
  点数 515 = 515
```

**这不是「差不多」，是逐字相同。**

减细做的是「把已有节点沿法向平移」，
不改变点的数量，也不改变轮廓的划分。

## 五、这次验证的价值

### 1. 「视觉印象」必须用数据校验

我看到「永」字的 SVG，觉得底部点密、点数多，
立刻推测是减细造成的。

**扩到 10 个字一统计，推测完全错误。**

单个字的观察可能是特例——**样本量不够就下结论，是这轮最大的风险**。

### 2. SVG 锚点视图揭示了「看不到的结构」

纯渲染图只能看墨迹轮廓，看不出：
- 笔画是独立轮廓还是连笔
- 控制点密度分布
- 锚点类型（on/off）

**SVG 带锚点的视图揭示了这些，这是纯像素对比做不到的。**

### 3. 与优质参考对比，能发现「我们没走的路」

如果只跟自己比，永远不知道 OPPO 用连笔合并。

**知道有这个选项，才能判断「我们选了哪条、为什么」。**
我们的答案是：跟随 Noto 的笔画分离路线（铁律所限，也是合理选择）。

## 六、结论

| 项 | 结果 |
|---|---|
| 我们轮廓数 vs Noto | **52 = 52，完全相同** |
| 我们点数 vs Noto | **515 = 515，完全相同** |
| 减细是否增加控制点 | **否** |
| 「永」底部密集点簇 | **Noto 原生**，非我们引入 |
| OPPO 的差异 | 连笔合并（轮廓数减半），设计哲学不同 |
| 铁律「只移动节点」 | **已验证** |

但这是**单字观察**，本轮未扩大到足够样本验证。
