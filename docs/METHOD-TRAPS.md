# METHOD-TRAPS：验证方法与已知盲区

> 本项目共出现 **20+ 次**「数据看起来是缺陷、实际正常」或「工具本身不可靠」。
> 本文档汇总所有验证手段的**可靠度**与**已知盲区**，供后续维护者避坑。
>
> 最后更新：2026-11-06（P62）

---

## 一、工具可靠度分级

### A 级：所见即所得，可作最终判据

| 工具 | 用途 | 为什么可靠 |
|---|---|---|
| **渲染像素统计** | 墨量、字面尺寸 | 直接数实际画出来的点，无中间抽象 |
| **`hb-shape`**（对 TTF）| 分段、advance、特性 | 与浏览器同源的排版引擎 |
| **Chrome `document.fonts`** | 加载成功性 | 真实浏览器环境 |
| **`ots-sanitize`** | 浏览器可加载性 | 就是浏览器用的那个清洗器 |

### B 级：可靠但要注意口径

| 工具 | 用途 | 注意 |
|---|---|---|
| **`read_points`**（轮廓坐标）| 拓扑、点数、bbox | 原始数据，最精确；但**不是**墨量 |
| **`BoundsPen`** | 包围盒 | 只给外框，不含内部结构 |
| **`fontTools.getBestCmap`** | 码位覆盖 | 读的是 format 12，不是 format 4 |
| **哈希（sha256）** | 文件一致性 | 可靠；但**不能**代替内容正确性检查 |

### C 级：有已知盲区，必须交叉验证

| 工具 | 盲区 | 详见 |
|---|---|---|
| **`AreaPen` 总和** | **受轮廓绕向影响**，内轮廓同向会「加」而非「减」 | P60 / P61 |
| **`hb-shape` 对 WOFF2** | **返回 gid0 且不报错**，静默失败 | P43 |
| **文件大小** | 改几个字节大小不变，无法判断是否过期 | P41 |
| **单点宽度测量** | 中文字宽恒定，测不出字体是否生效 | P45 / P56 |
| **小字号渲染** | hinting/栅格影响大，1px 误差可达 11% | P53 |

## 二、五个必须记住的具体陷阱

### 陷阱 1：`AreaPen` 受绕向影响

```python
# 错误：跨字体比较面积
area = abs(AreaPen(gs).value)      # 内轮廓同向时会相加

# 正确：逐轮廓取绝对值再求和
total = sum(abs(contour_area))     # 与绕向无关

# 或最可靠：数渲染像素
```

**实测影响**：816 字形有绕向抵消，`O` 只有真实墨量的 29%，`copyright` 只有 20%。

### 陷阱 2：HarfBuzz 不解 WOFF2

```bash
hb-shape --font-file=x.woff2 "永和"   # 返回 gid0，退出码 0，无任何错误提示
```

**所有在 WOFF2 上做的 hb 测试结论都无效**，必须解包成 TTF。

修复方式：
```python
f = TTFont(path); f.flavor = None; f.save("/tmp/x.ttf")   # 注意：可能需 2 分钟
```

### 陷阱 3：中文字宽恒定，测不出字体是否生效

| 字符集 | 不同字体宽度 | 能否判断生效 |
|---|---|---|
| 中文（全角）| **完全相同**（1000/1000 upm）| **不能** |
| 拉丁（比例宽）| 不同 | **能** |

**验证「字体是否生效」必须用拉丁字符。**

### 陷阱 4：测试字符本身的特殊部位

| 目的 | 该用 | 不能用 |
|---|---|---|
| 测基线 | A x H | **g j p q y**（有下伸）|
| 测字面 | 国 口 | **（）""**（有上伸下沉）|
| 测横画 | 一 | **二**（两条横，扫描会混）|

P58 用 `g` 测基线，得出「字母偏下 19px」的错误结论。

### 陷阱 5：度量口径不统一

| 现象 | 错误口径 | 正确口径 |
|---|---|---|
| 「减细不均匀」| 看**比率**（0.75~0.91 起伏）| 看**差值**（恒 11-12，σ=0.5）|
| 「档位分配不均」| 看我们自己 | **对比 Noto 同档**（增量完全相同）|
| 「字面缩水」| 渲染像素 vs 轮廓坐标混用 | 同一口径内比较 |

## 三、验证前必问的五个问题

```
1. 这个工具本身可靠吗？（查本文档第一节）
2. 我测的字符有特殊部位吗？（陷阱 4）
3. 该跟参照字体对比吗？（多次误判源于「只看自己」）
4. 我用的口径对吗？（比率 vs 差值 / 像素 vs 坐标）
5. 结论对哪个版本有效？（产物变了要重验）
```

## 五、一句话总结

> **孤立看数据容易误判；
> 对比参照 + 选对口径 + 用眼睛确认，三者缺一不可。**

这三条分别对应：

| 手段 | 作用 | 不能替代 |
|---|---|---|
| **对比参照**（Noto/OPPO/鸿蒙）| 判断「正常还是异常」| 不能证明我们自己内部一致 |
| **选对口径**（比率/差值、像素/坐标）| 让数据说真话 | 不能证明视觉效果好 |
| **用眼睛看**（渲染图）| 发现数据测不出的问题 | 不能量化 |

## 六、本文档的陷阱已逐条实测复现

为避免「凭记忆写文档」导致错误（P44/P50 教训），
本轮对关键陷阱做了复现验证：

### 陷阱 2：HarfBuzz 不解 WOFF2 ✓ 复现

```
$ hb-shape --font-file=WDesignSansSC-Regular.woff2 永和
[gid0=0+500|gid0=1+500]        退出码 0，无任何错误提示

$ hb-shape --font-file=WDesignSansSC-Regular.ttf 永和
[gid23015=0+1000|gid12144=1+1000]   正常
```

注意 woff2 的 advance 也错了（500 而非 1000）—— **完全静默的错误结果**。

### 陷阱 3：中文字宽恒定 ✓ 复现

```
我们 Regular  永和九年  总宽 = 4000
Noto 400      永和九年  总宽 = 4000    ← 完全相同
```

四字 × 1000 upm = 4000，任何字体都一样。
**这证实：用中文测不出字体是否被应用。**

### 陷阱 1：AreaPen 绕向抵消 ✓ 一致

```
字形 O:  abs(AreaPen) = 159234
绝对面积和（P61 实测）   = 551702
比值                     = 0.289
```

与 P61 记录完全一致。

**三条关键陷阱均已实测确认，文档结论可靠。**
### 陷阱 6：容器限制截断测量

**现象**：画布固定 1400px，七个字重全部报「宽度 1400」。
看起来像「字重不影响宽度」，实际是**文本超出画布被截断**。

**正确做法**：先用工具问真实尺寸，再建容器。
```python
adv = font.getlength(text)          # 先问 FreeType 真实宽度
img = Image.new("L", (int(adv)+40, 140))   # 再建画布
```

**同类问题**：测量数组长度、固定采样点数、时间窗口截断——
都会让「工具的限制」伪装成「被测对象的特性」。
