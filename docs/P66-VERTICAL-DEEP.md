# P66：竖排深度验证（字形位置与标点处理）

## 动机

P25 验证过竖排「功能是否正常」（advance 恒 -1000、有 vert 特性）。
本轮深入一层：**字形在格子内的位置、标点是否正确旋转**。

## 一、验证用例

| 用例 | 内容 | 检查点 |
|---|---|---|
| 中文竖排 | 永和九年 | advance、格内位置 |
| 括号竖排 | （国）| 括号是否旋转 90° |
| 引号竖排 | 「国」| 引号位置调整 |
| 逗号竖排 | 国，年 | 逗号移到右上 |
| 破折号竖排 | 国—年 | 破折号是否转竖 |

## 二、结果：advance 完全一致，格内位置差 6-7 单位

| 用例 | 我们 | Noto | advance |
|---|---|---|---|
| 中文竖排 | −873 / −874 | −880 | **都是 −1000** ✓ |
| 括号竖排 | −868 / −874 | −880 | **都是 −1000** ✓ |
| 引号竖排 | −874 | −880 | **都是 −1000** ✓ |
| 逗号竖排 | −872 / −874 | −880 | **都是 −1000** ✓ |
| 破折号竖排 | −874 | −880 | **都是 −1000** ✓ |

### advance 是竖排的核心指标

竖排 advance **必须恒为 −1000**（每字一格，向下）。
**五个用例全部一致**，说明竖排字距正确。

### 格内位置差 6-7 单位是什么

`hb-shape` 竖排输出格式：
```
gid23015,0@-500@-500,-873+0,-1000
         │      │       │      └─ advance = -1000  ✓
         │      │       └──────── 字形基线在格内的纵向位置
         │      └──────────────── y 偏移（居中调整）
         └─────────────────────── x 偏移（居中调整）
```

我们 −873 / Noto −880，**差 6~7 单位**。

## 三、换算：亚像素级，不可见

```
upm = 1000
6.5 / 1000 = 0.65% em

16px 字号: 6.5 × 16/1000 = 0.10 px
100px 字号: 6.5 × 100/1000 = 0.65 px
```

**在任何实际字号下都小于 1 像素。**

## 四、为什么会有这个差异

竖排格内位置取决于**字形的视觉高度中心**。

P52 实测：
```
国字顶部:  我们 789  vs  Noto 779   (+10)
国字底部:  我们 -74  vs  Noto -72   ( -2)
```

我们的字形**顶部高 10 单位、底部低 2 单位**，
视觉中心略微上移 → 竖排格子内位置略上。

**这是「字面略微放大」的连带效果，不是排版缺陷。**

## 五、标点处理验证

括号、引号、逗号、破折号的 gid 与 Noto **完全相同**：

| 字符 | 我们 gid | Noto gid | 一致 |
|---|---|---|---|
| （ | 58994 | 58994 | ✓ |
| ） | 58995 | 58995 | ✓ |
| 「 | 59006 | 59006 | ✓ |
| 」 | 59007 | 59007 | ✓ |
| ， | 58979 | 58979 | ✓ |
| — | 58990 | 58990 | ✓ |

说明 `vert` 特性把相同的字形换成了相同的竖排变体，旋转与位移规则一致。

## 六、结论

| 项 | 结果 |
|---|---|
| 竖排 advance | 五用例**全部 −1000** ✓ |
| 标点 gid | 六个标点**与 Noto 完全相同** ✓ |
| 格内位置 | 差 6-7 单位 = **0.65% em（亚像素）** |
| 差异原因 | 字面放大连带，非缺陷 |
| 竖排可用性 | **完全正常** |

## 七、教训

**「数值不同」不等于「有问题」，先换算到实际影响再说。**

看到 −873 vs −880 第一反应是「竖排对齐有偏差」。
换算后发现 16px 下只有 0.1 像素——
**连一个像素的 1/10 都不到**。

判断差异是否可接受，标准应该是「实际渲染是否可见」，
而不是「数值是否完全相同」。
